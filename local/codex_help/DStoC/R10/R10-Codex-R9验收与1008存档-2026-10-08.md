### 交接报告的一处计数笔误

原始 `r9_dataset_manifest.json` 按 `(case,scan,object_id)` 计数，五个物体分别为：

| 物体 ID | 观测 | 裁剪 |
|---|---:|---:|
| Flashlight | 31 | 31 |
| Magazines | 25 | 50 |
| hand_grenade | 28 | 56 |
| smoke_bomb | 26 | 52 |
| smoke_bomb_01 | 35 | 70 |
| 合计 | **145** | **259** |

DS 报告把后四项的部分裁剪数写入“观测”列，其中 `smoke_bomb_01` 的观测数留空。总数与数据清单无冲突，属于报告错误；DS 应修正报告，避免以后误把重复裁剪当独立样本。145 次观测来自清单中 **35 张不同源图**（不是 145 张原图）；留出集与训练集共享这五个资产 ID，结论只覆盖同资产换摆位。

## 三、R10 启动前的阻断项（交 DS 修，勿开始训练）

1. **协议读取必然报错。**`_r9_train_lora_v2.py::mode_eval()` 读取 `proto['max_new_tokens']`、`proto['num_beams']`、`proto['classes']`；实际 JSON 分别在 `proto['generation']` 和 `proto['v0_scope']` 下。现有 `--eval-holdout --baseline` 与新 adapter 留出评估不能按启动包执行。先改为读取正确字段，并对协议 SHA、四类列表、生成参数做静态断言；把改后脚本 SHA 写入新交接记录。另补一例重复 `class` 键的解析检查：当前 `json.loads` 默认吞掉重复键，与“严格单字段”承诺不符。
2. **评估单位错位。**`mode_eval()` 逐个裁剪调用模型，`score()` 逐裁剪计分；留出是 **56 次观测、99 张裁剪**，而冻结协议要求同一观测的两个边距先合成结果，再按观测、按物体统计。必须按 `(case,scan,object_id)` 聚合，保留每视图原始答案；缺视图、两视图不一致、显式 `unknown`、无效 JSON 分别记录原因，再按事先冻结的优先级形成一次观测的最终状态。不得把 99 张裁剪当 99 件实物。
3. **协议的 `unknown_explicit` 与融合 `undecided→unknown` 命名冲突。**现在“四类互斥计数”无法准确描述两视图不一致。应另存协议新版本（如 `r9_v0_class4_v2`，旧 v1 保留），明确观测级字段和协议失败优先级；改脚本引用并在输出记录新协议 SHA。不要在看模型结果后改规则。
4. **`--smoke` 的换图证明不充分。**脚本使用 `rows[0]` 与 `rows[1]`，通常是同一原图的两个边距；模型仍在 `train()`，LoRA dropout 也可使相同图的 loss 不同。R10 真正冒烟时应固定随机性、关闭 dropout 做同图重复对照，再换一张不同原图并比较视觉输入或 logits；若失败，进程必须返回非零状态，不能只打印 `SMOKE FAILED` 后以 0 退出。
5. **启动包的 `| tee` 会掩盖失败退出码。**R10 命令在每个管道前设置 `set -o pipefail`，并在冒烟及评估输出中核对成功标记；否则 Python 失败时 shell 可能仍因 `tee` 返回 0 而继续。

以上第 1–3 项属于 **R9 准备代码与冻结口径的修正**，无需模型权重、训练或仿真即可检查。第 4 项先改冒烟方法，实际冒烟仍留给用户启动 R10 后的 DS。修复后提交代码差异、静态检查结果、协议版本与 SHA；Codex 复核通过后再走备份门。
