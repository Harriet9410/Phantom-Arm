2. 用户要求的备份门完成：服务器 Git 阶段提交、本地同步、Gitee/GitHub 两端实际推送并核对提交 SHA；`D:\MYCODE\TCEI\1008存档.zip` 与逐文件校验通过。当前服务器 Git 根是 `/root`，HEAD `b9e8a34`，**没有配置远端**；ZIP/Git bundle 不等于两远端推送。训练入口若在备份后修改，补存修正版及 SHA。不得把 9GB 权重或 ZIP 推到 Git 远端。

## 2. DS 的执行顺序与每步停门

### A. 四类旧路径基线（训练前，仅一次）

用修复后的评估程序，在固定 s03/s04 和四类协议上，复现当前在线分类路径：加载旧定位 adapter、分类时关闭它；保存每视图原始回答、融合决定、按五个物体的混淆矩阵和协议 SHA。旧五类 `5/8/27` 不作同比。**看到基线结果后不改提示、划分、边距或评价公式。**

### B. 单样本真实多模态冒烟

以训练解释器 `/opt/conda/envs/inference/bin/python3` 加载基座；先固定随机性、关 dropout 做**同一图重复**对照，再换另一张原图、保持文字和目标答案不变，检查视觉张量/embedding 或 logits 确实改变。随后只做**一个**前向、反向及优化步，输出设备、峰值显存、耗时、答案 token 掩码、loss、梯度非零的 LoRA 参数完整路径；确认视觉塔、resampler、旧 adapter、基座其余权重没有被更新。

任一项失败、OOM、NaN 或脚本只打印失败而退出码为 0，**立即停止**；交原始日志和最小反例，不进入完整训练。命令管道须 `set -o pipefail`。

### C. 一次预注册训练

冒烟通过才按已冻结配置训练一次。保留基座和旧 adapter，检查新 adapter 输出目录在运行前不存在；每 epoch 记录 loss、样本数、优化步数、耗时、显存峰值，保存唯一检查点和 `train_config.json`（基座/数据/协议/脚本 SHA、类表、目标模块、超参数、时间）。训练中不能读取留出结果。若仅因显存不足需改 batch/累积步数，应新建配置版本，说明等效批量与学习率关系；若模型前向或标签出错，先修实现并重新冒烟，不把失败训练当实验成绩。

### D. 一次冻结留出评估

用与 A 完全同一四类输入、两视图合成、生成预算、解析和观测单位，只把“旧分类路径”换成**启用新分类 adapter**。输出每视图原文、融合结果、`correct_known / wrong_known / unknown_or_undecided / protocol_failure`，并按五个物体 ID 与 s03/s04 分组。保留原始 JSON、脚本/模型/协议 SHA；比较 A→D 的改进。

**离线过门**：两个留出场景各五件实物在预先固定的**最早两次扫描**内均得到正确类别；任何时刻错误已知类别为 0，协议失败为 0。早期 unknown 可由第二次扫描消解，但要逐项报告。若缺一件或错认一件，**不接入运行包**。同一留出反复调参再宣称通过无效；若首轮失败，先分析图像、真值关联、输入与模型，再由 Codex 决定是否收集新摆位数据并设新的留出，或改用另一条视觉基线。

### E. 接入候选，不直接覆盖稳定运行版

离线过门后才创建独立运行候选并锁定文件哈希。`nine_node.py` 当前对分类请求 `grounding=False` 会关闭已加载 adapter；**仅把 `grounding_adapter` 路径换成新 adapter 不会生效，且可能损伤定位**。优先让同一基座按请求用途切换命名 adapter：定位请求用旧 adapter，分类请求用新 adapter；如果当前 PEFT 接口不支持安全切换，再评估两实例的显存。所有切换在模型锁内完成，日志记录请求用途、实际激活 adapter 名称/路径和结果；异常时回到旧版，不允许无声降级或把真值表塞进运行时。

分类接入后复测旧定位能力和分类能力，再合入经独立复核的 C 修复（unknown 发布/计数、等待与最终校验同口径）。B 与 C 分阶段提交，保留 R7 回退点；不要同时重写机械臂动作策略或工程目录。

### F. DS 仿真验收（Codex 不代跑）

1. **定向四案**：按 s01、s03、s02、s04 跑横平竖直场景；首两案任一出现错认、错抓、错误去向、掉件未恢复或整轮失败，即停下定位根因，不继续刷剩余案。
2. **官方与十案**：定向过门后，用**同一提交、同一模型和配置**跑官方五条指令完整轮次及 B03 十个横平竖直摆位；每案记录五条指令的目标/数量/去向、物理拿取与放置、整轮结束状态、时间预算和失败事件。十案不是运行时位置答案表，也不是模型训练集。
3. **判定**：官方轮次和十案都必须由原始任务日志证明五条指令正确闭环且预算内完成；“物体都上带”“4/5”“分类离线正确”均不能代替整轮通过。若失败，按分类→语义决策→抓取轨迹→物理反馈的因果链定位，**只改与失败相关的层**，修正后以新候选和清楚版本重验受影响门。三十个倾斜场景不进入 V0 门。

### G. 干净 V0 封装与移交

全部在线门通过后：把运行必要代码、配置、模型/adapter 路径与哈希、启动/停止说明、依赖索引、回退说明、已知限制写入发布包；清理动态 `state/active_*` 与开发期脚手架，不混入 `cases_scramble10` 真值或评分程序到运行时。保留一个明确源提交及 BUILD/PACKAGE 清单。封包后**不改行为、不重命名工程文件**；用户再克隆实例，在克隆上重构和准备实机。
