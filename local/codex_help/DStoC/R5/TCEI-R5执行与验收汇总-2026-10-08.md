## 四、P0 核心证据：类别漂移的完整审计路径（决定性）

九格审计（`_stack/logs/perception.log`）逐扫描记录 `scan_class/old_class/old_pending/stored_class/full/decision`：

**s02 真实烟雾弹 @(672,350)，10 次扫描：**
```
1 new              scan=Smokegrenade  -> stored=Smokegrenade   (full)
2 same             scan=Smokegrenade  -> stored=Smokegrenade   (full)
3 pending_conflict scan=Torch         -> stored=Smokegrenade   pending=Torch
4 pending_conflict scan=Grenade       -> stored=Smokegrenade   pending=Grenade  ← 覆写
5 pending_conflict scan=Torch         -> stored=Smokegrenade   pending=Torch
6 confirmed_reclass scan=Torch        -> stored=Torch          ← 改判（错）
7-10 same          scan=Torch         -> stored=Torch
```

**s04 @(672,350)**：`new Smoke → pending Torch → same Smoke → pending Torch → confirmed_reclass Torch → pending Grenade`

**s05 @(660,352)**：`new Grenade → same ×2 → pending Torch → confirmed_reclass Torch → pending Grenade → same Torch ×2`

### 因果判断
- **事实**：三个案的真实物体（B03 案卷真值分别为 Smokegrenade/Grenade）第一次**全量**扫描类别正确；随后扫描在**三类之间闪烁**；`confirmed_reclass` 把存储类别改成错误类别。
- **事实**：`pending` 槽**逐次覆写**，因此"当前 == 上一次 pending"并不等于"两次连续独立一致"——s02 第 5、6 次虽连续为 Torch，但中间（第 4 次）曾出现 Grenade；s04 的两次 Torch 之间夹了一次 `same Smoke`。
- **推断（强）**：`confirmed_reclass` 门对**三值闪烁**无效，是第五项 `stable_identity_class_changed` 阻断的直接上游。漂移在九格识别层完成，**早于** `perception_tracking`F1a 的六帧投票——故调 F1a 门槛治不了本链。
- **未证实**：为何该位置全量扫描会得出三类闪烁（可能与该物体的裁剪外观/姿态、或九格对烟雾弹与手雷/手电筒的混淆有关）；本轮审计只记录扫描级决定，未保存每次扫描的原图与裁剪。
- **反例（不退化对照）**：s03 t5 在同版本下发起并成功；s02 首个全量扫描类别正确说明识别链并非一律错。

### 与 Codex 假说的对照
Codex R5 提出"6 帧可能只代表一次扫描的重复标签"——本轮以审计证据进一步确认为**更上游**的问题：漂移在九格的两轮门就已发生，且该门的"两轮"可被非连续样本满足。

基于第四条证据，最小修复点应在 **`nine_classify.py` 的改判门**，而非 F1a：
1. **连续一致性**：要求替代类别在**连续 N 次（如 2-3）全量扫描**中一致，且期间**无冲突类别插队**（当前 `pending` 覆写正是漏洞）；

3. **可信基线保护**：对一个已 `full` 验证过的新物体，改判要求更强的证据量（如 N≥3）；
4. 保留 `stable_identity_class_changed` 阻断；不放宽类别拒单；改判需留 `reclass_audit` 且**绑定 stable_id 的受审计路径**（Codex R5 原文要求）。
