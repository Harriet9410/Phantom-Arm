## 2. P0-2 训练脚本接口取证与五项修正

### 2.1 源码取证结论（`/root/inference/FM9G4B-V`，只读文件）

| 事实 | 证据位置 |
|---|---|
| 模型是 **InternVL 系 `FM9GV`** | `config.json` `architectures:["FM9GV"], model_type:"fm9gv"` |
| 正确入口是 `processor(...)` 一次性产出全部输入 | `modeling_fm9gv.py::chat()`：`inputs = processor(prompts_lists, input_images_lists, return_tensors="pt", max_length=...)` 后 `inputs.pop("image_sizes")` |
| 图像占位串与展开 | 文本放 `(<image>./</image>)`；`image_processing_fm9gv.py::get_slice_image_placeholder` 展开；`im_start=<image>`/`im_end=</image>`、`image_feature_size=64`、`max_slice_nums=9`、`patch_size=14` |
| processor 返回键 | `processing_fm9gv.py::_convert_images_texts_to_inputs` → `input_ids`（**左 padding**）、`attention_mask`（pad=False）、`pixel_values`、`image_sizes`、`image_bound`（每图 `[start,end)`）、`tgt_sizes` |
| 网络前向签名 | `FM9GV.forward(self, data, **kwargs)`；`get_vllm_embedding(data)` 读 `data['input_ids'/'image_bound'/'pixel_values'/'tgt_sizes']`；随后 `self.llm(input_ids=None, position_ids=..., inputs_embeds=vllm_embedding, **kwargs)` |
| **注意力是 MLA**（无 `q_proj/k_proj/v_proj`） | `modeling_fm9g.py::FM9GAttention`：`q_a_proj`、`q_b_proj`、`kv_a_proj_with_mqa`、`kv_b_proj`、`o_proj`；MLP：`gate_proj`、`up_proj`、`down_proj` |
| 视觉侧须排除 | `FM9GV.vpm`（`SiglipVisionTransformer`）、`FM9GV.resampler`（`Resampler`）；另排除 `lm_head`、`score` |

**由此得出旧脚本的根因**：旧 `TARGET_MODULES=('q_proj','k_proj','v_proj','o_proj','Wqkv',...)` 在本模型上**一个都匹配不到**（`discover_targets` 会打印实际线性层名后退出）；旧 `encode()` 的 `tokenizer(text)+batch['images']` 路径**缺 `image_bound`/`tgt_sizes`/占位符展开**，图像不会进入计算。

### 2.3 其它修正（超出五项但属同一因果链）

### 2.4 实测验证（仅 tokenizer+processor，**未加载模型权重**）

`--check-labels` 输出（两条样本，`scramble_01` 的 `smoke_bomb` 两个边距）：

| 字段 | 值 | 含义 |
|---|---|---|
| `seq_len` / `n_real_tokens` | 184 / 184 | 单样本无 padding |
| `image_token_span` | **[9, 73]** | **64 个图像 token** = `image_feature_size`，占位符展开正确 ✓ |
| `answer_start` / `answer_end` | 171 / 181 | 答案区段 |
| `n_kept_tokens` | 10 | 参与损失的 token 数 |
| `kept_text` | `{"class": "Smokegrenade"}` | **逐字等于**期望答案 |
| `kept_equals_expected` | **true** | 掩码自校验通过 ✓ |

**掩码修正过程（三轮，均有实测证据）**：
1. 初版按"独立编码答案长度取尾部 N token" → 实测尾部解码为 `"Smokegrenade"}<|im_end|> \n`（**开头被切、混入终止符**）→ 否决；
2. 改差异法（两个不同答案比首个分歧）→ 实测 `kept_text='Smokegrenade"}'`，因为两答案**共享前缀 `{"class": "`**，分歧点在类名处 → 否决；
3. 最终改为"**与仅提示版本（`add_generation_prompt=True`）的 token 长度对齐**"→ 实测 `kept_text` 逐字正确 ✓。

### 2.5 解析器与计数（不需要模型）

13 个解析用例：正确/带空格/带围栏 → `correct_known`；显式与大小写 `unknown` → `unknown_explicit`；越界类名、额外字段、错键名、非 JSON、截断、空、非字符串 → `protocol_failure`。**13/13 PASS**。
`score` 四类互斥且覆盖全部样本（已验证），`per_object` 按物体汇总正确。

### 2.6 仍未验证项（→ R10 冒烟，逐条列出）

1. `forward(data, **kwargs)` 的 **kwargs 实际接受集**：`get_vllm_embedding(data)` 是否只从 `data` 读视觉输入、`labels` 是否被 `self.llm` 正确接收。静态读码支持该结论，但**未经真实前向验证**。
2. LoRA 目标命中路径的实际清单与可训练参数量。
3. 换图是否改变计算（`--smoke` 的 loss 差异断言）。
4. 答案区段的**反向**是否真的只更新答案 token 相关的梯度（`n_trainable_tensors_with_grad > 0`）。
5. 显存占用与单步耗时（决定 batch/步数），以及 4 epoch 总时长——**本轮不承诺任何运行时间**。
