# R9 验收与 V0 收敛决定（Codex 撰写）

日期：2026-10-08。依据：R9 的 DS 报告、原始 JSON、数据构建与训练脚本，以及本次从服务器重新读取的运行版清单、训练脚本、数据清单。**本次没有运行训练或仿真。**

## 结论

**不能冻结 V0。**当前服务器运行版仍为 `codex_v0_r7_candidate_20261008`；R9 分类方案只做了离线验证，没有部署。40 次物体观测中，两视图方案正确 5、错认 8、未知 27，四个场景均未达到五件物体全部识别。直接训练现有脚本也不可取：dry-run 没覆盖真正的多模态前向路径。

R9 有进展：它把阻碍 V0 的核心问题定位到**当前图像与分类模型之间的适配**，并保留了可复核原始记录。现在应只处理这条主线，停止扩展动作优化、30 个倾斜场景和项目重构。

## 核查结果：事实与限制

1. 服务器 `tcei_stack/BUILD_MANIFEST.json` 和 `PACKAGE_MANIFEST.json` 均标记 R7 候选；服务器训练脚本、数据 `summary.json`、`manifest.json` 的 SHA256 与 R9 本地副本完全相同。服务器**没有 R9 分类方案已上线**的证据。
2. 离线主方案 `5/8/27`、备方案 `1/18/21`，合计各 40 次；烟雾弹主件的 8 次观测均错认为手雷。这里的 40 次是**观测次数**，不是 40 个独立物体；同一批物体在不同扫描中反复出现。结果足以否决当前候选，不能外推为对真实世界的总体准确率。
3. 数据清单有 145 次观测、259 个裁剪，训练 s01/s02、留出 s03/s04。**场景划分成立，物体身份划分不成立**：`Flashlight`、`hand_grenade`、`Magazines`、`smoke_bomb`、`smoke_bomb_01` 五个物体 ID 均同时出现在训练和留出。交接文档“按场景划分无泄漏”只对场景成立；脚本的 `(case, object_id)` 检查无法发现跨场景同物体的外观泄漏。留出集只能验证**同一资产换摆位**，不能验证陌生实物。
4. 训练数据中 `CompressedFood` 为 0；五类输出仍包含它。任何四类留出分数都不能证明第五类可用。若线上任务确有该类，冻结前必须取得真实该类图像并单独验收；不能删类或宣称五类全覆盖。

## 训练脚本的阻断项：DS 先修再执行

文件：服务器 `/root/ds_r9_train_lora.py`，本地 R9 `_r9_train_lora.py`。

1. `AutoModel.from_pretrained(...)` 后没有 `.to('cuda')` 或有效 `device_map`，但每批输入直接 `.to('cuda')`。正式路径很可能设备不一致，dry-run 无法发现。先做**一条样本**的真实前向、反向与参数更新冒烟检查；失败立即停。
2. `encode()` 只把纯文本对话放进 tokenizer；仅在模型暴露 `process_images` 时附加 `images`，未证明该模型要求的图像占位符、视觉张量及位置与在线 `model.chat()` 一致。请直接参照该模型源码的训练接口构造样本，并证明**替换图片而保持文本相同时视觉输入确实改变模型计算**。否则训练可能只记住答案文本。
3. `labels=b['input_ids']` 对用户提示和答案全段计算损失。改为只对助手的 `{"class":"..."}` 答案 token 计算损失，提示、图像占位符和 padding 位置置 `-100`；检查至少一个有效答案 token。
4. `discover_targets()` 仅按线性层末段名称筛选，没有检查模块路径，不能支持“LoRA 只在语言侧”的声明。打印并固定完整命中路径，排除视觉编码器及不应训练的模块；保存可训练参数清单。
5. 训练评估现在把所有无合法类别输出归入 `unknown`，未独立统计协议失败，和报告声称的“四项计数”不一致。把显式 `{"class":"unknown"}` 与无效 JSON、额外字段、截断分开。评估必须沿用线上同一图片预处理、同一适配器状态、同一 5 类提示和同一 `max_new_tokens=32` 等参数。

以上是**代码静态检查**，不等于已观测到正式训练失败；第 1、2 项必须由 DS 做最小模型冒烟检查确认。不要直接启动 4 epoch 训练。

## 最短执行路线与停止门

**DS 下一步仅交付 B：**修复训练管线 → 单样本真实前向/反向冒烟检查并记录输入张量、有效答案 token、可训练模块与显存 → 用固定划分训练一次 → s03/s04 按独立物体观测汇总混淆矩阵，并给出五类覆盖边界。训练时保留原数据和模型不覆盖；失败时交原始错误、日志、检查点，不继续调提示或扩场景。

如果模型训练接口无法在短时间内正确接入，可用现有带标签裁剪做**一次固定的视觉基线**（例如图像特征最近邻）与 s03/s04 留出对照，判定是否有更短的仿真 V0 路线；不能把同一资产的换摆位分数称为实机泛化。这只是备选，不是并行开新一轮试错。

**B 通过门：**留出集零“错误已知类别”；五件物体在在线调用预算内均能给出正确类别；协议失败为零。`CompressedFood` 若是线上必需类别，补齐真实样本及独立验收。任一条件未过，就不接入服务器运行版。

**B 过门后才做 C 与冻结：**把适配器接入分类分支（现有 `grounding=False` 会关闭适配器，仅改路径不会生效），锁定版本和哈希；由 DS 在四个已测横平竖直场景跑定向仿真，逐任务核对拿取、放置、类别、整轮完成与时间预算，提交原始日志及可复现命令。Codex 验收后封装只含运行必需文件的干净 V0，再由用户克隆。任何“物体都上带”都不能替代“整轮指令正确通过”。

**现阶段进度判断：**R9 解决了诊断，不是解决了分类；距可冻结 V0 至少还差“有效分类器 + 真实在线整轮证据”两道门。无法据现有记录可靠估计具体剩余小时数。
