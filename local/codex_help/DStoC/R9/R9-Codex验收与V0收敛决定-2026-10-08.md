# R9 验收与 V0 收敛决定（Codex 撰写）

日期：2026-10-08。依据：当前 R9 目录中 DS 已交付的预备材料、原始 JSON、数据构建与训练脚本，以及本次从服务器重新读取的运行版清单、训练脚本、数据清单。**用户尚未启动正式 R9 执行；现有 R9 材料是预备工作。本次没有运行训练或仿真。**

## 结论

**不能冻结 V0。**当前服务器运行版仍为 `codex_v0_r7_candidate_20261008`；R9 分类方案只做了离线验证，没有部署。40 次物体观测中，两视图方案正确 5、错认 8、未知 27，四个场景均未达到五件物体全部识别。直接训练现有脚本也不可取：dry-run 没覆盖真正的多模态前向路径。

R9 预备工作有进展：它把阻碍 V0 的核心问题定位到**当前图像与分类模型之间的适配**，并保留了可复核原始记录。现在应只处理这条主线，停止扩展动作优化、30 个倾斜场景和项目重构。

## 核查结果：事实与限制

1. 服务器 `tcei_stack/BUILD_MANIFEST.json` 和 `PACKAGE_MANIFEST.json` 均标记 R7 候选；服务器训练脚本、数据 `summary.json`、`manifest.json` 的 SHA256 与 R9 本地副本完全相同。服务器**没有 R9 分类方案已上线**的证据。
2. 离线主方案 `5/8/27`、备方案 `1/18/21`，合计各 40 次；烟雾弹主件的 8 次观测均错认为手雷。这里的 40 次是**观测次数**，不是 40 个独立物体；同一批物体在不同扫描中反复出现。结果足以否决当前候选，不能外推为对真实世界的总体准确率。
3. 数据清单有 145 次观测、259 个裁剪，训练 s01/s02、留出 s03/s04。**场景划分成立，物体身份划分不成立**：`Flashlight`、`hand_grenade`、`Magazines`、`smoke_bomb`、`smoke_bomb_01` 五个物体 ID 均同时出现在训练和留出。交接文档“按场景划分无泄漏”只对场景成立；脚本的 `(case, object_id)` 检查无法发现跨场景同物体的外观泄漏。留出集只能验证**同一资产换摆位**，不能验证陌生实物。
4. 训练数据中 `CompressedFood` 为 0；五类输出仍包含它。任何四类留出分数都不能证明第五类可用。若线上任务确有该类，冻结前必须取得真实该类图像并单独验收；不能删类或宣称五类全覆盖。

## 训练脚本的阻断项：R9 修改并静态检查，R10 才实际运行

文件：服务器 `/root/ds_r9_train_lora.py`，本地 R9 `_r9_train_lora.py`。

1. `AutoModel.from_pretrained(...)` 后没有 `.to('cuda')` 或有效 `device_map`，但每批输入直接 `.to('cuda')`。正式路径很可能设备不一致，dry-run 无法发现。R9 修正设备配置；**R10 首先做一条样本**的真实前向、反向与参数更新冒烟检查，失败立即停。
2. `encode()` 只把纯文本对话放进 tokenizer；仅在模型暴露 `process_images` 时附加 `images`，未证明该模型要求的图像占位符、视觉张量及位置与在线 `model.chat()` 一致。请直接参照该模型源码的训练接口构造样本，并证明**替换图片而保持文本相同时视觉输入确实改变模型计算**。否则训练可能只记住答案文本。
3. `labels=b['input_ids']` 对用户提示和答案全段计算损失。改为只对助手的 `{"class":"..."}` 答案 token 计算损失，提示、图像占位符和 padding 位置置 `-100`；检查至少一个有效答案 token。
4. `discover_targets()` 仅按线性层末段名称筛选，没有检查模块路径，不能支持“LoRA 只在语言侧”的声明。打印并固定完整命中路径，排除视觉编码器及不应训练的模块；保存可训练参数清单。
5. 训练评估现在把所有无合法类别输出归入 `unknown`，未独立统计协议失败，和报告声称的“四项计数”不一致。把显式 `{"class":"unknown"}` 与无效 JSON、额外字段、截断分开。评估必须沿用线上同一图片预处理、同一适配器状态、同一 5 类提示和同一 `max_new_tokens=32` 等参数。

以上是**代码静态检查**，不等于已观测到正式训练失败；第 1、2 项必须由 DS 在 R10 做最小模型冒烟检查确认。R9 不加载模型，不做单步前向/反向，不启动 4 epoch 训练。

## 正式 R9：只交训练之外的准备，不动运行版

DS 按优先级交付，做完 P0 就结束本轮；时间有余才做 P1。**不跑训练、单步反向、模型推理或仿真；不部署 B/C 候选；不改服务器当前 R7 运行包。**已有 R9 离线结果作为预备证据，不为凑轮次重跑。

### P0：让 R10 一开始就能训练

1. **数据台账**：核对 145 次观测/259 裁剪的来源、真值关联及重复关系；按“场景、物体 ID、原图、裁剪”四层分别计数，显式写明训练/留出共享五个物体 ID。检查类别覆盖，若现有归档里有 `CompressedFood` 真值图片就补入隔离数据；没有就写“缺样本”，不得伪造或用留出集训练。
2. **修训练脚本**：落实上节五项；从 FM9G4B-V 的实际模型源码确认训练所需的图像占位、预处理、forward 参数与答案掩码。若接口无法静态确认，记录精确阻断点和 R10 所需最小试验，不能宣称“管线就绪”。脚本默认不执行训练；训练命令单独列出。
3. **冻结评估协议**：明确一次观测的两视图如何合成最终类别，`unknown` 与协议失败分别计数；固定 s01/s02 训练、s03/s04 留出、五类提示、生成预算、分类分支适配器开关和检查点命名。输出一个不可随结果改动的评估脚本/配置。可做不加载模型的语法、数据、标签与解析器检查。
4. **R10 启动包**：列出服务器脚本路径、SHA256、数据清单 SHA256、基座/旧适配器路径、所需磁盘和显存的待测项、单样本冒烟检查命令、完整训练命令、留出评估命令、失败停止条件和回退路径。保存到 R9，注明 DS 撰写。不得把未测的运行时间写成承诺。

在**独立候选副本**中，按 R8 文档 §4-C 修 `nine_classify.py` 的 unknown 计数/发布、`semantics.py` 的 unknown 相关性与排除条件，以及 `nine_node.py` 的等待与最终校验口径；只做静态/单元检查，记录逐文件差异和回退。先不要把新适配器默认打开，也不要把 C 候选接进当前运行版。若 P0 还没完成，P1 直接延后，不因它拖住 R10。

## R10 才开始训练、评估与接入

1. DS 先做单样本真实多模态前向/反向，记录图像张量、答案有效 token、可训练模块、损失和显存；验证换图像会改变输入/计算。失败立即停止并交日志。通过后按 R9 固定配置训练一次，保留基座和原适配器；不要边看留出结果边调提示或划分。
2. 用 s03/s04 评估，同一物体的多次扫描要同时给出逐次结果和**按物体汇总**结果。判据：零错误已知类别、在线调用预算内五件均正确、协议失败零。这个留出只验证同资产换摆位；若 `CompressedFood` 属线上必需类，另补真实样本和独立验收。未过门不得接入运行版。
3. 通过后才把适配器接入分类分支（现有 `grounding=False` 会关闭适配器，仅改路径不生效），锁定版本和哈希；再合入已复核的 C 修复。DS 在四个已测横平竖直场景做定向仿真，逐任务核对拿取、放置、类别、整轮完成与时间预算，提交原始日志及可复现命令。Codex 验收后封装干净 V0，再由用户克隆。“物体都上带”不能替代“整轮指令正确通过”。
