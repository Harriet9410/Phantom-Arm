# 入口 B：指令控制台说明

> 核对日期：2026-10-06。依据 `evaluation/instruction_console.py`、`scripts/run_round.py`、`tcei_stack/episode_driver.py`。控制台是 Tkinter 操作前端，命令 `bash robot.sh console`；运行根目录和数据目录在源码中分别固定为 `/root/tcei_final_v2_23/tcei_260920v2`、`/root/gpufree-data/tcei_260920v2`。

## 操作顺序

1. 在服务器起好栈，看到“已就绪，尚未下发抓取任务”。控制台**不会自动读取栈状态**；启动回合时由 `run_round.py` 拦截未就绪、重名、空夹爪或证据盘不足等问题。
2. 逐条核对指令 1～5。五个框永远预填官方默认场景的示例文字；控制台**不读取** `case.json`。B03 等位置变化场景，应先打开该 case 的 `instructions` 数组，按本场内容覆盖。清空的输入框会跳过。
3. 点“生成指令文件”，再点“启动回合”。前者写 `RUNS/manual_<日时分>.json`；后者后台运行 `robot.sh run <同名回合> --instructions <文件>`。改了输入框后，必须重新生成，否则启动的还是上一份 JSON。
4. 看状态区和本轮日志。状态区约每 1.6 秒读 `episode/summary.json`；详情看 `/tmp/manual_<日时分>.out`、回合 `logs/episode.log` 和 `episode/events.jsonl`。`summary` 未出现前“执行中”只是显示状态，不能证明任务已经准入。
5. 结束时查看 `supervisor_finished.json` 的记录器关闭、执行开关和安全停止状态。需要新场景，正常执行 `bash robot.sh stop`，然后用新名称 `start`。

## 按钮背后的程序

| 按钮/区域 | 当前源码行为 | 需注意 |
|---|---|---|
| 指令 1～5 | 从输入框收集非空行，顺序保持。 | 默认文字是硬编码示例，可能与当前 case 不匹配。 |
| 生成指令文件 | `on_generate` 将 JSON 数组写到数据目录；记住文件路径。 | 文件名 `%d%H%M` 只到分钟，同一分钟重复生成会覆盖文件；同名回合目录已有则 `run` 拒绝。 |
| 启动回合 | `on_launch` 用 `setsid nohup` 后台启动 `robot.sh run`；默认预算 600 秒，共用一轮。 | 按钮收到 `LAUNCHED` 仅表示外层 shell 发起，结果要查回合证据。 |
| 取消当前回合 | 调用 `bash robot.sh cancel`，要求取消和实测停止回执。 | 停止状态以返回值和证据为准。 |
| 回合间复位 | 临时写 `/tmp/entryb_reset.py`；尝试复位仿真停止锁、重启 controller、删除栈 `round_started.lock`。 | 它没有重新摆场景，且清锁/重启属于实验路径；当前脚本与 `drill5.py` 的复位顺序不同。不要凭“复位完成”推定物体、进程归属和夹爪均已恢复。 |
| 状态区 | 轮询 summary，显示成功条数、回合状态和最近三条结果。 | 它不检查真实落带画面，也不显示完整证据。 |

## 多条指令如何执行

控制台把所有非空行作为**同一轮**交给 `run_episode.py`。`EpisodeDriver` 顺序处理，整轮共用预算。前一条成功后处理下一条。当前版中，计划接受前的 `rejected/request_rejected/plan_rejected` 会走 `mission_ledger.release_rejected_task()`；能证明目标未被触碰且账本已了结，才继续下一条，否则停轮。物理失败能否继续还取决于实测停止和释放条件。它不是五个独立回合，也不会替每条自动恢复场景。只想测试一条，其他四框要清空。

## 与 A 入口的关系

```text
控制台输入 → JSON 指令文件 → robot.sh run → run_round.py
    → 记录器 + 执行开关 → run_episode.py / EpisodeDriver
    → 九格选择 / 语义校验 → controller → Isaac → summary
```

B 入口保留 A 入口的准入、记录、哈希和停止链，只改变指令来源及启动方式。`run_round.py` 还会核对四节点进程归属、预热标志、冻结运行时、空夹爪、相机新鲜度及数据盘空间。控制台没有给这些校验开后门。

## 四个常见误解

- **看到五条预填，不表示当前场景有配套指令。** 它们写在 `instruction_console.py` 的 `examples` 数组；B03 的逐场指令以 case JSON 为准。
- **点“启动回合”不等于已成功。** 后台发射后的准入错误、语义拒绝、动作失败及证据缺口都可能让回合失败。
- **状态区“成功 N 条”不等于比赛 N 分。** 它只数 summary 中的 `task_succeeded`；还要看对象、传送带侧、物理轨迹、证据完整性和裁判口径。
- **“回合间复位”不等于重新起栈。** 需要可复现的初始五件布局时，用 `stop → 新栈名 start → 新回合名 run`。复位按钮仅在明确知道场景残留和锁存条件的实验中使用。

具体命令与目录见《使用手册》，内部模块与 ROS 数据流见《代码与技术路线导读》。
