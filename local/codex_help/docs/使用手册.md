## 快速开始

> 默认场景的最短流程；B03/B02 指定布局见 1.2。图形控制台预填的是默认场景五条，不会随 case 自动改文字。

```bash
cd /root/tcei_final_v2_23/tcei_260920v2
bash robot.sh doctor
bash robot.sh start demo_$(date +%Y%m%d_%H%M%S)
bash robot.sh console
# 在控制台核对指令 → 生成指令文件 → 启动回合；结束后核对 summary 与 supervisor_finished
bash robot.sh stop
```

栈名和回合名必须唯一。`start` 只预热，不执行抓取；`run` 才开启动作。若需重新得到原始五件布局，用 `stop → 新栈名 start → 新回合名 run`。

## 一、起栈（每次开始必做）

> 仿真启动的是**默认**场景（5 物品原始布局：烟雾弹×2、手电筒、弹夹、手雷）
>
>

```Bash
cd /root/tcei_final_v2_23/tcei_260920v2
bash robot.sh start bisai_stack_$(date +%Y%m%d_%H%M%S)
```

- 栈名**不能重复**（重名报 FileExistsError）；带到秒的时间戳可降低重名概率，但仍应检查旧目录

- 查已有栈名：`ls /root/gpufree-data/tcei_260920v2/`

- **就绪标志**：末尾出现 `已就绪，尚未下发抓取任务`（约 1\-2 分钟）

- 起栈即加载默认场景 \+ 五物体

### 1\.1 选择检测器

**九格（默认）/ YOLO（****`--detector`****）**

**默认 = 纯九格**，不加任何参数就是这个；只有做对照实验时才需要切：

```Bash
bash robot.sh start bisai_stack_$(date +%Y%m%d_%H%M%S)                 # 默认：九格检测
bash robot.sh start yolo_stack_$(date +%Y%m%d_%H%M%S) --detector yolo  # 对照：检测器换成 YOLO
```

||纯九格（默认）|`--detector yolo`|
|---|---|---|
|分类/出框|九格大模型（FM9G4B\-V \+ LoRA）|YOLO（`/root/jaka/best.pt`）|
|YOLO 权重|**不加载**（零 YOLO 合规形态）|加载|
|语义规划（选哪个物体）|九格节点|九格节点（**仍然启动**）|
|用途|当前默认链路；赛规结论以正式规则和运行证据为准|对照实验；不得把 YOLO 结果记作纯九格成绩|

切换只对**新起的栈**生效；已起的栈要停掉重新 `start`。

### 1.2 场景与题库

**不加 `--case`**：使用官方原 USD 的五件物资原始摆位。指定 case 时，`harness/original_layout_sim.py` 在官方场景内改已有物体的摆放，等待物理稳定并记录测试真值；它不增加新物体。启动前会核对 case 与登记表的 SHA256、case_id、seed、planner_seed。`--case-register` 不写时默认 B01，因此 B02/B03 必须显式指定。

| 场景 | 命令中的文件 | 用途 |
|---|---|---|
| B03 十场景 | `cases_scramble10/scramble_01.json` + `B03_SCRAMBLE10_REGISTER.json` | 位置变化、物体保持平放态；优先按本场 `instructions` 检查，最接近已知比赛形态。 |
| B02 三十场景 | `cases_official30_v2/official_random_05.json` + `B02_AVAILABLE30_REGISTER.json` | 带角度随机布局的扩展挑战；历史目录名不代表官方赛题。 |
| B01 三十场景 | `cases_b01/random_02.json` + `B01_REGISTER.json` | 历史回归。 |

```bash
bash robot.sh start b03_01_$(date +%Y%m%d_%H%M%S) \
  --case cases_scramble10/scramble_01.json \
  --case-register B03_SCRAMBLE10_REGISTER.json
```

场景启动失败先看该栈的 `scene_setup_error.json` 和 `logs/`。B03 部分 JSON 残留旧的“随机 yaw”文字/`yaw_delta_degrees`，实际写入姿态以 `quaternion_wxyz` 与仿真真值为准。改整个 USD 场景还涉及相机和手眼标定、空间约束与模型适配，不是换一个 `--case` 就能解决。修改冻结运行核心时也要同步 `BUILD_MANIFEST.json`。

## 二、发指令（两种方式）

### 方式一：终端发一轮

默认场景的官方五条，可由标准入口一次发出：

```bash
bash robot.sh run round_$(date +%Y%m%d_%H%M%S) --official-example
```

原稿记录的五条文字仍是：

1. 抓取左上方的烟雾弹，放到左侧传送带
2. 抓取右下方的弹夹，放到右侧传送带
3. 抓取最左方的军用手电筒，放到左侧传送带
4. 抓取手雷，放到右侧传送带
5. 抓取剩余的物品，放到左侧传送带

指定场景时先核对该 case 的 `instructions`；指令文件应是 UTF-8 JSON 字符串数组，内容与本场匹配。例如：

```json
["抓取右下方的弹夹，放到右侧传送带"]
```

```bash
bash robot.sh run round_$(date +%Y%m%d_%H%M%S) \
  --instructions /root/gpufree-data/tcei_260920v2/本场指令.json \
  --budget 600
```

预算 `--budget` 默认 600 秒，上限 600 秒，**整轮共用**。同一栈执行过一轮后，标准入口不允许重复执行；原稿的“逐条发 → `manual_reset.sh` → 下一条”属于共享栈实验做法，不是可复现的标准流程。单条独立测试需要新的场景栈和回合名；若需同一场景中五条连续任务，把本场五条放进同一个 JSON。计划接受前被语义拒绝时，当前账本若确认目标未被触碰，可以结清该条继续；有抓放痕迹或证据不足时停止。物理失败能否继续取决于实测停止和释放证据。

### 方式二：控制台图形化

```bash
bash robot.sh console
```

原稿的“填指令 → 生成指令文件 → 启动回合”顺序仍正确。五个输入框预填的是固定示例；B03 按该 case 的 `instructions` 覆盖，空行不执行。改文字后必须重新生成 JSON。控制台只负责发射，回合准入、记录和动作仍由 `robot.sh run` 接管。详细按钮和复位边界见《控制台说明》。

### 可视化开关（跟在 run 命令末尾）

|参数|效果|
|---|---|
|（不加）|无任何窗口|
|`--viewer`|弹出 bbox 实时小窗（800×450，框随物动 \+ 底部候选清单）|
|`--panel`|弹出核对面板（全功能：相机、标注、执行状态）|
|`--viewer --panel`|两个都弹|

示例：

```Bash
bash robot.sh run ${S}_1 --instructions ... --budget 210 --viewer
```

### 控制台 \+ bbox 小窗配合（零改动方案）

控制台的"启动回合"**不传 \-\-viewer 参数**，所以不会自动弹小窗。但 bbox 小窗是纯订阅者（只监听话题，不关心回合怎么发），**独立拉起一次即可持续显示**：

**先拉小窗（执行一次，持续挂着）**：

```Bash
cd /root/tcei_final_v2_23/tcei_260920v2
setsid nohup /usr/bin/python3 -u evaluation/bbox_window.py > /dev/null 2>&1 &
```

桌面上弹出 bbox 小窗，**不随回合结束关闭**，一直显示实时画面。

**再用控制台正常操作**：

```Bash
bash robot.sh console
```

填指令 → 生成 → 启动 → 看小窗里的实时标注和任务状态。小窗是只读观察者，不负责复位；下一轮是否能执行仍以新栈和准入检查为准。

**不想看了直接点小窗 X 关掉。**

|组合|效果|
|---|---|
|小窗 \+ 控制台|图形化发指令 \+ 实时 bbox 画面（**训练推荐**）|
|小窗 \+ 终端逐条|终端发命令 \+ 实时画面|
|只开小窗|纯看画面不发指令|
|只开控制台|发指令不看画面|

> 核对面板（`bash robot.sh panel`）同理——也是纯订阅者，独立拉起即可与小窗/控制台并存。

## 三、核对成绩（全部跑完后）

先看本轮 `episode/summary.json` 的每条结果，再看 `supervisor_finished.json` 的 `evidence_complete`、执行开关和停止状态；必要时对照 `rgbd/`、`scalars/`。`task_succeeded` 是程序判定，不等于独立比赛评分。

当前一轮可先用实际回合名检查：

```bash
R=实际回合名
cat /root/gpufree-data/tcei_260920v2/$R/episode/summary.json
cat /root/gpufree-data/tcei_260920v2/$R/supervisor_finished.json
```

原稿下面的循环只适用于当时按 `${S}_1`～`${S}_5` 命名的逐条历史回合；新演练不要直接照抄旧回合名。

以下是原稿的逐条回合名批量核对示例；现在请把名称换成本次实际运行的回合名：

```Bash
for r in ${S}_1 ${S}_2 ${S}_3 ${S}_4 ${S}_5; do echo "== $r =="; python3 -c "
import json
s=json.load(open('/root/gpufree-data/tcei_260920v2/$r/episode/summary.json'))
t=s.get('tasks',[{}])[0].get('result',{})
print(t.get('status'), 'placed=', t.get('placed_verified'))"; done
```

控制台方式的回合名（`manual_<日时分>`）：

```Bash
for r in /root/gpufree-data/tcei_260920v2/manual_*.json; do
  n=$(basename $r .json)
  ep=/root/gpufree-data/tcei_260920v2/$n/episode/summary.json
  [ -f "$ep" ] && python3 -c "
import json
s=json.load(open('$ep'))
tasks=s.get('tasks',[])
ok=sum(1 for t in tasks if (t.get('result') or {}).get('status')=='task_succeeded')
print('$n', '成功 %d/%d' % (ok, len(tasks)))"
done
```

## 四、清理与恢复

```bash
cd /root/tcei_final_v2_23/tcei_260920v2
bash robot.sh status
bash robot.sh stop
df -h /root/gpufree-data
```

`stop` 会要求受控停止确认，只结束本包记录的进程，保留历史证据。若提示停止未确认或仿真尚活而控制器缺失，先保留现场并检查栈 `logs/`、`pids/`，不要把原稿中的 `pkill -9`、`rm -rf` 当常规恢复命令；它们可能破坏进程归属和失败证据。缺空间时先归档并确认具体回合目录，再单独决定清理。需要重新摆场景时，停止后用新栈名启动。
