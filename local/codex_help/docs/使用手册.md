# TCEI 使用手册

> 核对日期：2026-10-06。对应服务器活动包 `/root/tcei_final_v2_23/tcei_260920v2`。这是操作顺序，不是性能验收报告。先确认 `tcei_stack/BUILD_MANIFEST.json` 的版本及当前栈 `launch.json`；本文核对时服务器为 `dev_v7_t1_46`，仍标注开发版、待抓取验证。

## 0. 准备与选择场景

在服务器的 **Jupyter 终端**进入活动包：

```bash
cd /root/tcei_final_v2_23/tcei_260920v2
bash robot.sh doctor
```

首次部署的新实例先按包内《部署说明》运行 `bash robot.sh init`，再 `doctor`。确认桌面、ROS/Isaac 和数据盘正常。命令都由 `robot.sh` 分发；不要同时用旧 `isaac_grasp.cpp` 链路发运动命令。

| 目的 | 场景与登记表 | 说明 |
|---|---|---|
| 官方默认场景 | 不传 `--case` | 原场景五件物品；演示时可用官方五条指令。 |
| B03：比赛形态优先 | `cases_scramble10/scramble_01.json` + `B03_SCRAMBLE10_REGISTER.json` | 十个场景位置变化，姿态保持横平竖直；**指令按各 case 的 `instructions` 字段逐场核对**。 |
| B02：扩展鲁棒性 | `cases_official30_v2/official_random_01.json` + `B02_AVAILABLE30_REGISTER.json` | 历史目录名含 `official30`，但这三十个有随机角度，不应称为官方比赛题库或与 B03 混算。 |
| B01：历史回归 | `cases_b01/random_01.json` + `B01_REGISTER.json` | 早期失败复测，不代表比赛形态。 |

case 启动会按登记表核对文件散列、case_id、seed 和 planner_seed，先摆位并等待稳定；不能只改 JSON 不更新登记表。控制台预填的五条始终是固定示例，它不会读取当前 case 的指令。对 B03 先打开相应 case JSON，核对 `instructions`，再填控制台。

B03 的生成脚本 v5 实际用默认平放姿态，并可能绕竖直轴转 90°；个别 case 保留旧模板的 `randomization` 与 `yaw_delta_degrees` 文本，不能用这两项判断实际角度。以 `quaternion_wxyz` 和起栈后的物理场景为准。

## 1. 起栈

每个栈使用新的、唯一的名称。默认纯九格检测：

```bash
bash robot.sh start stack_$(date +%Y%m%d_%H%M%S)
```

指定 B03 第一场示例：

```bash
bash robot.sh start b03_01_$(date +%Y%m%d_%H%M%S) \
  --case cases_scramble10/scramble_01.json \
  --case-register B03_SCRAMBLE10_REGISTER.json
```

对照实验才加 `--detector yolo`；默认 `nine` 不加载 YOLO 权重。`start` 成功会显示“已就绪，尚未下发抓取任务”，表示四节点预热且尚未执行。失败时查看该栈目录的 `logs/`、`scene_setup_error.json`，不要复用已创建的名字。

## 2. 发指令

### A. 终端发一轮

官方默认场景的固定五条：

```bash
bash robot.sh run round_$(date +%Y%m%d_%H%M%S) --official-example
```

其他场景先按 case 的 `instructions` 准备 UTF-8 JSON 字符串数组，再发：

```bash
bash robot.sh run round_$(date +%Y%m%d_%H%M%S) \
  --instructions /root/gpufree-data/tcei_260920v2/本场指令.json \
  --budget 600
```

`--budget` 大于 0 且不超过 600 秒，默认 600 秒；是**一整轮共用**，不是每条各 600 秒。回合名和栈名都要唯一。`run_round.py` 会检查四节点、空夹爪、图像新鲜度、冻结清单和至少 8 GiB 空闲，再启动证据记录器与动作。一个已运行过的场景不能再次通过标准 `run` 复用。

### B. 桌面控制台

```bash
bash robot.sh console
```

逐项核对输入框中的五条文字；指定 case 时按该 case 的 `instructions` 覆盖。**留空的行不执行**。先点“生成指令文件”，再点“启动回合”。状态区读 `episode/summary.json`，详细报错看 `/tmp/manual_*.out` 及本轮 `logs/episode.log`。控制台不自动判断栈是否就绪，准入检查仍由 `run_round.py` 执行。

控制台文件名只精确到日、时、分：同一分钟再次生成会覆盖指令 JSON，若同名回合目录已存在，启动会被拒绝。改变文字后必须再点“生成指令文件”。“回合间复位”是实验性脚本，含控制器重启和清锁；它与 `scripts/drill5.py` 的复位实现及校验顺序不同，不宜把按钮成功输出等同于场景已恢复或下一轮已安全就绪。正式可复现演示建议完整 `stop` 后用新名称 `start`。

多条放同一回合时，`EpisodeDriver` 顺序处理。当前版本对**计划接受前**的语义拒绝会尝试用账本了结该任务，确认未触碰目标时继续下一条；若已有抓放证据或账本无法了结，整轮停止。物理失败能否继续取决于实测停止和释放证据。一次填五条不等于每条自动独立重试。

## 3. 看画面与看结果

只读画面可独立打开：

```bash
bash robot.sh panel
```

终端 `run` 可加 `--viewer` 或 `--panel`；控制台按钮启动不传这些参数，可另开 `evaluation/bbox_window.py`。可视化窗口是观察者，窗口关闭不等于任务已停。

```bash
bash robot.sh status
```

结果以数据盘 `/root/gpufree-data/tcei_260920v2/<回合名>/` 为准：

| 文件 | 看什么 |
|---|---|
| `instructions.json`、`before_scene.json`、`runtime_manifest.json` | 指令原文、入场候选、实际运行版。 |
| `episode/events.jsonl`、`episode/summary.json` | 每条任务的语义、动作、失败原因和汇总状态。 |
| `supervisor_finished.json` | 记录器是否完整关闭、执行开关是否关闭、是否需要停止关注。 |
| `rgbd/`、`scalars/`、`logs/` | 画面、时序传感器和报错，供错物体/空抓/落带复核。 |

“窗口显示完成”“机械臂放手”“篮中物体变少”都不是独立成功证据。对比赛式 B03，逐条核对选中对象、传送带侧、物体实际落点、证据完整性与安全停止。成绩不能把 B03 与带角度 B02 混成一个通过率。

## 4. 取消与结束

需要停止当前任务时执行：

```bash
bash robot.sh cancel --reason '人工检查'
```

结束本栈：

```bash
bash robot.sh stop
```

`stop` 在仿真与控制器都存活时要求实测停止确认，随后只停本包记录的进程组；历史记录保留。若返回“尚未确认停止”或控制器缺失，先看进程状态和日志并保留现场，避免直接强杀 Isaac、删锁或批量删除数据。需要全新布局时，按顺序 `stop → 新名称 start → 新名称 run`。既有手册中的 `pkill -9`、`rm -rf`“万能恢复”会抹去进程/证据关联，已从常规操作卡移除。

## 5. 最短排查路径

1. 起栈失败：看 `<栈名>/launch.json`、`logs/`、`scene_setup_error.json` 和 `bash robot.sh status`。
2. 回合拒绝：先读终端或 `/tmp/<回合名>.out` 的准入错误，再看 `episode/summary.json` 的任务原因。
3. 动作异常：用 `events.jsonl` 对齐 `rgbd/` 与 `scalars/`；区分感知错误、语义错误、路径不可行、抓空、掉落和落带未证实。
4. 文件版本不符：核对栈 `launch.json` 和回合 `runtime_manifest.json`，不能只看当前编辑器中的源码。

代码原理与所有文件角色见《代码与技术路线导读》；B 入口的按钮和限制见《控制台说明》。
