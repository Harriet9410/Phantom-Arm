## 二、通用约定（三次都一样）

- ⚠️ **全部用单行命令**（多行 `\` 续行粘贴会丢反斜杠——10/4 实测教训）
- **栈名必须不重复**：时间戳写法 `$(date +%m%d%H%M)`
- **纯九格**：不加 `--detector`；审计 `<栈目录>/launch.json` 里 `"detector": "nine"`
- ⚠️ **`--case-register` 必须传 `B03_SCRAMBLE10_REGISTER.json`**（默认是 B01 的，传错报"不是已登记的 B01 布局"）
- **起栈成功两标志**：输出出现 `STRESS_SCENE_READY scramble_NN` + 栈目录有 `case.json`
- **控制台绑定激活栈**：每换新栈，关掉旧控制台窗口重新 `bash robot.sh console`
- **连打语义**：一次启动 = 5 条连打，任何一条被拒 → 整回合终止；被拒不纠缠，复位重发一次，仍拒记录跳过

## 六、结果判读（每次测完）

```bash
R=/root/gpufree-data/tcei_260920v2/manual_<时分秒>   # 控制台回合名

# 总览
python3 -c "import json;s=json.load(open('$R/episode/summary.json'));print(json.dumps(s,ensure_ascii=False,indent=1))" | head -60

# 关键事件统计
grep -oE '"grasp_tilt_fallback_started"|"placement_verified"|"task_succeeded"|"task_failed"|"released"' $R/episode/events.jsonl | sort | uniq -c
```

| 看什么 | 在哪 | B03 特有关注 |
| --- | --- | --- |
| 用的是九格 | `<栈目录>/launch.json` → `"detector"` | 应为 `nine` |
| 每条指令成败 | `summary.json` → `tasks[].result.status` | **规矩姿态下手电筒应回训练分布**（训练里它就是立放的）——三个场景手电筒条目若通过，即实锤"斜躺姿态 OOD"是 random_02 类失败主因 |
| 识别 | bbox 小窗 / `contact_sheet` | 立放/平放物体的类别是否正确、有无 unknown |
| 极端指令 | `grasp_tilt_fallback_started`、`unknown foreground may change` | S1 的"最左方"若仍被碎片门误杀 → 机制①②（重扫再验/碎片不算独立物体）的改动依据 |
| 放置核验 | `placement_verified` | `pending_verification` = 已知间歇问题，非本测试变量 |

**三次横向对比**：同一纯九格栈 + 规矩姿态 + 不同"类×方位"组合——失败若集中在手电筒条目 → 姿态 OOD 结论成立；若散布 → 问题在后段。
