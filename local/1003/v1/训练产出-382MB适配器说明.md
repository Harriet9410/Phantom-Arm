**那个 382 MB 是一个 LoRA 适配器文件**——文件名 `adapter_model.safetensors`，**382,337,688 字节**（≈364.6 MiB）。它是 9/29 第三轮 QLoRA 训练（`qlora_crop`）在**第 27000 步**存下的**最优检查点**，运行时由 `nine_node.py` 用 `PeftModel` 挂到基座 FM9G4B-V 上，**不修改基座本身**。

>
> 下文一律写**字节数或 382 MB**，指同一个文件。

## 前置知识：LoRA / QLoRA / PEFT 是什么（补充）

> 这是本文后面反复出现的几个词的解释。**读完这一节，下面所有内容都能看懂。**

### 1. 背景：为什么要"微调"

基座模型（FM9G4B-V，8.5GB）是别人在通用数据上预训练好的，**不认识我们的烟雾弹、弹夹、手电筒**。要让它干我们的活（看图 → 输出物体框），得用我们自己的 1200 张标注图再"教"它一遍，这个过程叫**微调（fine-tuning）**。

**全量微调**（把 62 层、几十亿参数全部重训一遍）的问题：
- 要存一整份新模型（又是 9GB）
- 显存要够（24GB 卡基本不够）
- 每换一个任务就得存一个 9GB 副本，非常浪费

### 2. LoRA：不训全部，只训一小块"增量"

**LoRA = Low-Rank Adaptation（低秩适配）**。核心想法一句话：

> **冻结原来的权重 `W`（一个都不改），在旁边加一对小矩阵 `A` 和 `B`，只训这两个小的。**

forward 时算的是 `W + B·A`——原来的知识（W）原封不动，新学的知识全装在 `B·A` 里。因为 `A`、`B` 很"瘦"（低秩），参数量比 `W` 小几个数量级，所以：

- 训出来的增量只有**几百 MB**（本项目就是那个 382 MB），不是 9GB
- 想换任务，就把这一小块**拆下来换一块**（所以叫 **adapter，适配器**——可插拔）
- 基座可以多任务共享，一份基座配多个适配器

几个必懂的超参（本文后面会用到）：

| 词 | 含义 | 本项目取值 |
| --- | --- | --- |
| **`r`（rank，秩）** | 那对小矩阵有多"宽"。越大越能学、也越大越容易过拟合 | **32** |
| **`alpha`（缩放）** | 控制新学部分对输出的影响强度，常按 `alpha/r` 折算 | **64** |
| **`dropout`** | 训练时随机丢弃，防过拟合 | 0.05 |
| **`target_modules`** | 把 A/B 挂到哪些层上（挂得越多越大） | **8 个 MLA 层** |

> **这就是为什么是 382 MB 而不是 9 GB**：LoRA 只存那对 `A`/`B`，不存基座。

### 3. PEFT / adapter / checkpoint —— 一堆近义词

- **PEFT** = Parameter-Efficient Fine-Tuning（参数高效微调）的**统称**，LoRA 只是其中一种（还有 DoRA、RSLoRA 等，本项目没用）。
- **adapter（适配器）** = LoRA 训完产出的**那组小权重文件**。本项目里就是 `adapter_model.safetensors` + 它的 config。
- **checkpoint（检查点）** = 训练过程中**每隔 N 步存一次**的快照。所以一个训练目录里会有 `step_9000`、`step_15000`、…、`final` 好几份。本项目 `save_every=3000` → 12 个检查点（见第六节，最优的**不是**最后那个）。

### 4. QLoRA：先把基座压成 4bit，再挂 LoRA

**QLoRA = Quantized LoRA（量化版 LoRA）**。在 LoRA 基础上多做一件事：

> **加载基座时用 4bit 量化（NF4），把 9GB 的基座压到约 2~3GB 显存，然后依然只训 LoRA 增量。**

- **量化**：把权重从 16bit/bf16 压成 **4bit** 存储（用 `bitsandbytes` 库，格式叫 **NF4**）。精度略降，但省大量显存。
- 训练时基座是**冻结的 4bit**，只有 LoRA 的 `A`/`B` 用高精度被更新。
- 本项目 `training_config.json` 里 **`load_in_4bit: true`** 就是它——**这也是"训练绝不改基座"的机制保证**：基座根本就是以量化只读形式加载的，改不了。

> **一句话对比**：LoRA = 只训一小组增量；**QLoRA = LoRA + 基座 4bit 量化**。本项目用的是 QLoRA。

### 5. 推理时发生了什么（"挂载"）

训练完，那 382 MB 的适配器要在**运行时**叠到基座上才生效：

```python
PeftModel.from_pretrained(基座, 适配器目录)   # 把 A/B 叠上去，等价于 W + B·A
```

- 基座**只被读取**，文件不变 → 这就是"9/29 训练没改模型本体"的最终答案。
- 还能**临时关掉**：`disable_adapter()` 让模型退回纯基座行为。本项目正是用它在"选块推理"时关掉适配器，只在"分类/出框"时启用。

## 二、它在哪里（同一份东西的三处存在）

| # | 位置 | 路径 | 状态 |
| --- | --- | --- | --- |
| ① | **实例（现行、运行用）** | `/root/sft_v2/outputs/qlora_crop/step_27000/adapter_model.safetensors` | 382,337,688 字节；`nine_node.py` 默认 `~grounding_adapter` 就指向这个目录 |
| ② | **9.29 存档（备份）** | `9.29存档.zip` → `存档/TCEI_jiuge_archive_20260929.tgz` → `outputs/qlora_crop/step_27000/adapter_model.safetensors` | **同一份**（本次已解包核对存在，大小一致） |
| ③ | **仓库** | — | ❌ **不入 git**（原因见下"为什么不入库"）。**注意：不入库 ≠ 不备份**，见本节的 ⚠️ |

> ⚠️ **只有这两个副本**：实例上的和 zip 里的。两者都在**同一台机器能碰到的范围**（实例 / 本机），若本机与实例同时损坏即失。适配器可重训，但成本约 12 小时 / 17 元，且需要那 1200 张裁剪图与 34 个脚本（zip 里有）。

### 2.1 为什么不入 git（但要备份）

**"不入库"只指不进 git 仓库，不代表它不需要备份。** 它运行必需、且只有两份同机副本——**该备份，只是不该放 git**。三个理由：

1. **体积超限，推不上去**：Gitee 免费版单文件上限约 50–100 MB、单仓总量约 500 MB；这个 **382 MB 单文件会被服务端直接拒**（`exceeds 100.00 MB`），且仓库已有 234 MB 源码，加进去连总容量一起爆。
2. **git 不适合二进制**：git 对二进制不存增量，每次改动存整份新 blob、永久留在历史、删要重写历史 → clone/fetch 越来越慢（与 8.5 GB 基座同类问题）。
3. **它是可再生产物**：能从数据+脚本重训（zip 内齐全），优先级低于**不可再生**的源码/补丁/工作记录。

**正确做法**：与**基座 tar 快照放同一处持久位置**（数据盘 / 对象存储），把"基座 + 适配器"一起快照——这才是补上"运行必需资产"缺口的做法。替代：Git LFS（免费版多不支持）/ Release 附件 / 分卷压缩。

> 配额数字有时效性，以 [help.gitee.com](https://help.gitee.com) 最新说明为准。

## 四、`adapter_config.json` 全文（这就是"训练改了什么"的清单）

```json
{
  "base_model_name_or_path": "/root/inference/FM9G4B-V",
  "bias": "none",
  "inference_mode": true,
  "init_lora_weights": true,
  "lora_alpha": 64,
  "lora_dropout": 0.05,
  "modules_to_save": null,
  "peft_type": "LORA",
  "r": 32,
  "target_modules": [
    "o_proj", "kv_a_proj_with_mqa", "q_a_proj", "q_b_proj",
    "kv_b_proj", "up_proj", "gate_proj", "down_proj"
  ],
  "task_type": "CAUSAL_LM",
  "use_dora": false,
  "use_rslora": false
}
```

**怎么读**：

- `base_model_name_or_path` = 基座路径，**只读**——说明这是加载在 FM9G4B-V 之上的增量，基座没被改。
- `r=32 / lora_alpha=64 / lora_dropout=0.05`：低秩秩 32，缩放 64，dropout 0.05。**注意**：训练脚本默认是 `alpha=32`，本轮实际用的是 **64**（`run_bbox_lora.sh` 的 `LORA_ALPHA` 环境变量覆盖）。
- `target_modules`：改的是 **8 个 MLA 专用线性层**（`q_a_proj / q_b_proj / kv_a_proj_with_mqa / kv_b_proj / o_proj / gate_proj / up_proj / down_proj`）。这是 FM9G4B（MiniCPM-3o 系）**注意力是 MLA 结构**，不能照搬 LLaMA 的 `q_proj/k_proj/v_proj`——脚本注释里专门写了这句。
- `task_type=CAUSAL_LM`、`use_dora=false`、`use_rslora=false`：标准 LoRA，没有用 DoRA/RSLoRA 变体。

**那 382 MB 权重里是什么**：以上 8 个层 × 每层一对低秩矩阵（`lora_A` 下投影 + `lora_B` 上投影），加上视觉侧可能的保存项。权重以 bf16 存（`safetensors` 头可查），键名形如 `base_model.model.<层名>.lora_A.weight` / `.lora_B.weight`。**没有基座权重**——所以只有 382 MB，而不是 9 GB。

## 九、它是怎么被用起来的（运行时）

`arm/tcei_stack/nine_node.py:73-91`（现行代码）：

```python
path = rospy.get_param('~model_path', '/root/inference/FM9G4B-V')
self.model = AutoModel.from_pretrained(path, trust_remote_code=True,
                                       attn_implementation='sdpa',
                                       torch_dtype=torch.bfloat16).eval().to('cuda')
self.tokenizer = AutoTokenizer.from_pretrained(path, trust_remote_code=True)
# Grounding (bbox) adapter: optional LoRA trained on top of the deployed model.
# Active only for classify requests; selection inference runs with the adapter disabled.
adapter = rospy.get_param('~grounding_adapter', '/root/sft_v2/outputs/qlora_crop/step_27000')
if adapter:
    from peft import PeftModel
    self.model = PeftModel.from_pretrained(self.model, adapter)   # 挂载，不改基座
    self._adapter_off = self.model.disable_adapter               # 选择推理时临时关掉
    self._grounding_loaded = True
```

- 基座先按只读加载 → 适配器**运行时叠加**（这就是"训练没改本体"的直接证据）。
- 适配器**只在分类/出框请求时生效**；选块推理用 `disable_adapter()` 临时关掉，保持原部署行为不变。
- 换适配器只需改参数 `~grounding_adapter` 指向别的目录，无需动基座。

## 十一、部署/复现必须记住的四条

1. **用 `step_27000`，不用 `final`**（差 0.04 IoU）。
2. **推理必须带 `--crop 260,51,1028,483 --upscale 1280x720`**，与训练预处理**完全一致**；漏掉会崩（实测 IoU 0.3796 → 0.0311）。
3. **换机器恢复**：把 `step_27000/` 整个目录（含 tokenizer / processor / `*.py`）拷到目标机的同一路径，或改 `~grounding_adapter` 参数指过去；基座另需单独恢复（见 `arm/docs/模型与环境恢复/`）。
4. **重训**：需要 `raw_images_crop/`（1200 图 + 标注）与 `scripts/`（34 个），两者都在 `9.29存档.zip` 内；按 `run_bbox_lora.sh` 的默认参数跑（注意实际用了 `LORA_R=32 LORA_ALPHA=64`）。
