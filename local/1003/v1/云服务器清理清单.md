## 二、先弄清"删了到底省不省空间"（overlay 分层）

`/` 是 overlay 文件系统，`/proc/mounts` 实测：

```
overlay / overlay rw,lowerdir=.../rootfs, upperdir=.../pvc-.../mount/upper_dir, ...
```

- **lowerdir = 镜像只读层**（打镜像时就有的内容）
- **upperdir = 容器可写层（PVC）**，`df` 报的 27 G 就是它
- **推论**：
  - **镜像自带**的目录（`isaacsim` / `inference` / `EAICON` / `ultralytics` / conda 环境…）→ 删除**不释放**系统盘，而且本来就必需 → **不要动**
  - **运行时产生**的目录（压测/测速/旧运行/训练输出）→ 在可写层，**删除真释放**
- **依据**：`df` 已用 27 G，而 `du /root/*` 合计 ≈ 47 G，差额 ≈ 20 G 即只读镜像层。

> 所以清理只针对"可写层里的历史产物"，不碰镜像自带的必需件。

### 10.7 `scalars/` 是什么，以及为什么"可删、但建议留"

**它是什么**：`evaluation/record_scalar_evidence.py` 的产物 —— 一个**只读** ROS 记录器（文件头自述 "Read-only native ROS evidence; no control publishers or truth feedback"：只订阅、**绝不发布**，也不回灌真值）。supervisor 把它与 `rgbd` 记录器作为两个独立进程拉起（`supervisor_finished.json` 的 `recorders` 里各一条，含 returncode / `recorded_rows` / `topics_seen`）。

**怎么记的**：对约 24 个话题，**每条消息一行 JSON** 追加写进 `scalars/events.jsonl`（行缓冲）：

```
{"topic":…,"received_wall":…,"received_monotonic":…,"last_received_simulation_time":…,"value":…,"callerid":…}
```

即"每个话题的每条消息 + 接收时刻 + 当时的 `/clock`"。话题涵盖 JAKA 关节/末端位姿/夹爪力/夹爪捕获、`/clock`，以及全部 `/tcei/*`（`request`/`plan`/`planner_status`/`task_status`/`nine_status`/`prepare_observation`/`candidates`/`gripper_contact`/`stop_*`/`cancel_*`/`grasp_preview_*`/`execute_preview`/`joint_diagnostics`…）。另有两个小文件：`ready.json`（必需话题齐备才写：`/clock`、关节、末端位姿、夹爪力、夹爪捕获）与 `closed.json`（`recorded_rows` / `topics_seen` / 时长上限）。

**🔑 关键**：`/tcei/candidates` 被**完整记录**并做了字段裁剪 —— 每条候选保留 `id / class / pixel / bbox / depth / world_position / confidence / grasp_ready / stable_id / identity_status / identity_reason / area / …`。
**所以 `scalars/events.jsonl` 本身就是"每周期候选清单 + 每个候选的类别/身份/面积"的完整时间序列。**

**与 `rgbd/` 的分工**：`rgbd` = 像素（相机帧对，200–1900 MB/轮，只用于**离线重算视觉**）；`scalars` = 数字与状态（3–89 MB/轮，能**事后还原决策链**）。两者都不参与评分（评分只读 `episode/summary.json` + `episode/events.jsonl` + `ground_truth.jsonl`），但 `scalars` 是唯一能逐帧回答"当时规划器看到的候选是什么、类别贴对没有、身份是否 confirmed"的**文本**证据。

**因此**：`rgbd` 删了只损失"回看画面/离线重跑视觉" → **优先删**；`scalars` 删了会损失整条时序决策链 → **建议保留**，只在 A 档仍不够用时才按 A′ 删。为 3.8 G 牺牲整条决策链不划算。

**三个必须记下的 API/工具坑（这次全踩了）**

1. **DELETE 必须带 `X-XSRFToken` 头**（与 PUT 同），否则 403，原文是 `'_xsrf' argument missing from POST` —— 会被误读成"服务器禁止删除"。
2. **`?content=1` 的目录列表会返回缓存旧值**：删完后列表仍显示 4791 个文件，让人以为没删掉。**验证必须用文件级 `?content=0` 探测（200/404）**，不能信列表。（同一个缓存也解释了此前 `?hash=1` 返回旧哈希的现象。）
