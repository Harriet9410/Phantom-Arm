## 二、random_02：识别错（视觉错 + 模型也错，守卫拦截正确）

**事件链**（events.jsonl L282-291）：模型 3 次回答完全一致 `{"class":"Torch","ids":["2"]}` → 3 次 `validation_failed: vision/model category disagreement` → rejected（`semantic_repair` 的 3 次上限用尽）。

**关键证据——发起时的候选索引**（L282 prompt 内）：
```
全类别候选ID索引：{"Smokegrenade":["1","2","3"]}
```
三个候选（真值应为 手电筒 + 手雷 + 1 烟雾弹）**全部被标成 Smokegrenade**。

**真值对照**（`scene_initialized.json` + 像素→世界投影复算）：
- 候选 id1（bbox 64×17 细长条，world≈[0.123,-0.021]）≈ **真手电筒**（truth [0.118,0.009]）
- 模型选的 id2（world≈[-0.053,0.020]）≈ 烟雾弹——**模型也选错了**
- 守卫 `semantics.py:332` 要求"所选候选的视觉类别==请求类别" → 拦截 = **正确行为**（防止把烟雾弹当手电筒抓走）

**识别为什么错**：
1. 首扫最关键的"全图编号查类别"票**超时**（perception.log：`nine locate timeout` ×2，10s 上限）——该票是双票+决胜票
2. random 布局**布局先验不激活**（只锚定默认场景像素位），分类全靠三视角投票
3. 手电筒 120° 斜躺 → 顶视 64×17 细长条 → **训练分布外**（见第四节）→ 被当烟雾弹
4. **类别滞回 + 身份 confirmed 锁死错误标签**；按需重扫是异步的（15~40s 落地），校验用的始终是缓存标签

## 三、random_06：误杀（视觉对、模型对，被未知碎片门拦下）

**事件链**（L299-301）：`infer_started` → 模型答 `{"class":"Torch","ids":["2"]}` → **一次** `validation_failed: unknown foreground may change the requested selection` → 直接 rejected（**0 次重试**——`ObservationRequired` 异常类不重试）。

**关键证据**：这次候选索引是**对的**：
```
全类别候选ID索引：{"Smokegrenade":["1","3"],"Torch":["2"]}
```
视觉正确、模型正确——杀死它的是 **unknown_regions 里的一个碎片**：
```json
{"bbox":[623,330,645,338], "pixel":[633.6,335.1], "reason":"unobserved_unverified_object",
 "stable_id":"f3934bf9-obj-0007", "seen_count":9, "class":"Torch", "possible_classes":["Torch"]}
```
**22×8 像素**、只见过 9 次——手电筒在任务 2 操作期间被部分遮挡产生的**残片**，被独立分类成了"另一个 Torch"。

**触发的守卫**（`semantics.py:419-427`）：
```python
needs_complete = quantity in ('all', 'implicit_unique') or relation in EXTREMES
if scene is not None and needs_complete:
    ...
    if any(_unknown_may_affect(region, category, relation, ...) for region in unknown):
        raise ObservationRequired('unknown foreground may change the requested selection')
```
"最左方" = **EXTREME** → 要求场景完整 → 存在"可能影响选择"的未知区域（一个可能的第二手电筒！）→ 拒绝。守卫逻辑上没错，但**认识论上错了**：那个碎片就是手电筒自己的遮挡残片，不是第二个物体。

**为什么前两条不死**："左上方/右下方"是象限指令，**不走 EXTREME 完整性门**。→ 每轮都死在第 3 条，是 **EXTREME 指令 + 场景已有抓取残留碎片** 的次序效应，不全是手电筒的问题。

## 四、训练数据：没有斜躺姿态（实锤）

**生成脚本** `gt_sft_gen.py`（工作副本已清理，从 git 恢复）：
- 从 `Content/JAKA/scene.usd` 批量采集，随机布局：随机物体组合 + 随机位置
- **位姿 = 只绕竖轴随机 yaw**（L212-220：`q = Gf.Quatf(cos(yaw/2), z·sin(yaw/2))`）
- 有 upright 分支（细长物体可竖立）但**数据里 0 个竖立样本**（未启用）
- **没有 case 那种 roll/pitch 斜躺**（120°/90°/180°）

**标注统计**（`/root/sft_v2/annotations/custom_bbox*.jsonl`，1200 图 / 4210 条指代样本）：

| 类别 | 样本数 | 框长宽比中位 | 横躺(>1.5) | 竖立(<0.67) |
| --- | ---: | ---: | ---: | ---: |
| Smokegrenade | 1699 | 1.45 | 45% | 0 |
| Magazine | 841 | 1.47 | 47% | 0 |
| Grenade | 839 | 1.79 | 64% | 0 |
| **Torch** | 831 | **1.18（近方形顶视）** | **仅 5%** | **0** |

**结论**：30 个 case 的物体姿态（带 roll/pitch 的斜躺/翻转）**整体在训练分布外**；手电筒落差最大——训练里近方形顶视，case 里 120° 斜躺成细长条。

## 五、为什么"手雷/弹夹行、手电筒不行"

1. **姿态落差最大**：训练近方形顶视（中位 1.18）↔ case 120° 斜躺细长条（实测 3.8）。斜躺的手电筒视觉退化为"一根圆柱"，正撞烟雾弹（圆柱）混淆族
2. **本就是最弱类**：9/29 训练评测 IoU@0.5：Torch **0.148**（四类最低）vs Smokegrenade 0.630 / Magazine 0.554 / Grenade 0.464
3. **次序效应**：第 3 条恰是 EXTREME 指令 + 场景已有抓取残留碎片（random_06 直接死于碎片误杀）
4. 手雷/弹夹的特征（椭球+网格纹、扁平弹匣+弹壳排列）更抗姿态变化；且它们在第 1、2 条时场景还干净

## 六、如果改，怎么改（分层，**均未实施**）

| 层 | 做法 | 成本 | 治什么 |
| --- | --- | --- | --- |
| **训练（根因）** | `gt_sft_gen.py` 位姿采样加 roll/pitch 随机（把 case 的 120°/90°/180° 甚至任意倾斜纳入采集），重采 1200 张 + 重训 QLoRA | ~12h / 17 元 | "斜躺不认识"（random_02 类死法） |
| **机制 ①** | EXTREME 指令被 unknown-region 拒时，**先触发重扫、等结果落地再验一次**（现在 `ObservationRequired` 直接终止） | 改 `semantics.py` / `episode_driver` + 刷 BUILD_MANIFEST | 误杀（random_06 类） |
| **机制 ②** | **极小碎片区域**（bbox < 30px、seen_count 低、与已确认候选位置重叠）不作为独立未知物体参与 `_unknown_may_affect` 判定——它大概率是确认物体的遮挡残片 | 改 `perception_tracking.py` / `semantics.py` | 误杀 |
| **机制 ③** | `category disagreement` 时**先重扫再验**（现在 3 次重答用的都是同一份过期缓存标签） | 改 `nine_node` / `semantic_repair` 流程 | random_02 类死锁 |
| 参数 | `classify_timeout` 10s → 20s（首扫全图查询超时是误标起点） | 1 参数 + 刷清单 | 超时票缺失 |
| **零改动战术** | 被拒后复位**重发同一条**（重扫落地后标签常已纠正）；EXTREME 指令单独一轮发 | 0 | 绕行，测试/比赛都可用 |

**建议排序**：机制②+①（治误杀，改动小、收益直接）→ 训练补姿态（治根）→ 参数顺带 → 零改动战术先行验证。
