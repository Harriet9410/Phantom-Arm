## 一、两条代码是什么关系

**它们不是两个版本，而是底座和上层。**

```
cc's_arm 运行层（tcei_stack）
  感知 · 九格 · 决策 · 抓取 · 证据 · 停止
  34 个模块，约 472 KB，7770 行
        ↑ 包一层接入，不改下面
────────────────────────────────
比赛源代码（官方给的）
  EAICON 场景与物资 · jaka_sim.py 仿真物理 · ROS 节点
  约 170 KB
```

关键设计：**cc's_arm 不修改比赛源代码**。它用 `sys.path.insert` 把官方 `jaka_sim.py` 导进来再包装，官方文件保持原样。原话是：

```python
sys.path.insert(0, '/root/EAICON/Source/JAKA')
import jaka_sim as original
# "Original files stay intact."
```

这么做有三个好处：官方镜像升级时不会被覆盖、出问题能对比官方行为、符合"用官方镜像和场景"的规则要求。

## 二、逐项改了什么

按模块列，最后一项是改动程度。

### 1. 启动方式

| | 比赛源代码 | cc's_arm |
| --- | --- | --- |
| 怎么启动 | 要开好几个终端，`launch` 文件里视觉和大模型的节点还是注释掉的，得手动拉起来 | 一个 `robot.sh`，`init / doctor / start / run / panel / status / cancel / stop` |

**程度：完全重写**

### 2. 进程管理

比赛源代码没有。cc's_arm 有进程组登记、`cancel` 会分配停止编号并核对实际停止回执、`stop` 只关自己登记的进程组。

**程度：新增**

### 3. 大模型接口（差别最大）

| | 比赛源代码 | cc's_arm |
| --- | --- | --- |
| 模型干什么 | 基本只被检查"有没有提到关键词" | 真正挑出要抓的物体、数量、目的地 |
| 坐标从哪来 | **用 YOLO 真值覆盖模型的回答** | 模型给编号，程序只校验，不替换 |
| 同类多件 | **不支持**（结果按类别存，同类只留一个） | 支持 |
| 说不清怎么办 | 没有这个机制 | 可以回 `needs_confirmation` 说明原因 |
| 校验 | 关键词在不在 | 独立的指令审计 + 不对就要求重答 |

比赛源代码的做法在日志里写得很直白：

```python
final = "%s(%d,%d,%.2fm,%.2f)%s" % (target_en, ...)
rospy.loginfo("坐标已用YOLO真值重构: %s", final)
```

**这里有个风险**：规则写着「九格语义解析是必选，未使用者直接判 0 分」。程序替模型把答案写好了，这一环按规则怎么认定要留意。

cc's_arm 反过来，在提示词里明确要求模型自己判断：

```
你是九格规划器，必须亲自理解原任务并观察全景编号图选择对象
```

**程度：完全重写**

### 4. 视觉感知

| | 比赛源代码 | cc's_arm |
| --- | --- | --- |
| 深度怎么取 | 只取物体中心**一个像素**，一个噪点就废 | 邻域中位数，还报告深度离散度 |
| 坐标 | 相机坐标系 | 完整换算到世界坐标（带标定） |
| 抓点 | 框中心 | 深度体中心（认得出的四类） |
| 物体身份 | 没有，每帧独立 | 有持续身份（`stable_id`） |
| 看不清的地方 | 没有这个概念 | 会标出未知区域、算遮挡比例 |
| 能不能抓 | 没有判断 | 有 `grasp_ready` |
| 排除机械臂自己 | 没有 | 用 URDF 正运动学算凸包遮罩 |

**程度：完全重写**

### 5. 抓取规划

| | 比赛源代码 | cc's_arm |
| --- | --- | --- |
| 动作 | 写死的一套，所有物体用同样偏移（下压 4 厘米） | 按物体实测几何算 |
| 抓多深 | 统一 -0.04 | 圆的（手雷/烟雾弹/手电筒）抓 65% 高、上限 28mm；默认取一半、上限 12mm |
| 等多久 | 固定 `sleep` 5 秒 / 3 秒 / 2 秒 | 到位窗口 + 实时反馈 |
| 抓点 | 一个 | 每个物体最多 5 个备选，逐次加深 4mm |
| 失败记忆 | 没有 | 每个物体单独记，不重复无效动作 |

**程度：完全重写**

### 6. 接触与力控

| | 比赛源代码 | cc's_arm |
| --- | --- | --- |
| 夹爪怎么合 | 位置量每次加 0.001，`gripper_is_captured` 变 True 就停 | 渐进预紧，0.25mm 一步，碰到力阈值就停 |
| 判据 | 一个布尔量 | 双指受力均 ≥0.2、持续 ≥0.45 秒、至少 3 个采样 |

要说明的是：**官方协议本身没有"力"的概念**（官方 readme 写明就是位置递增 + 布尔停止）。cc's_arm 是在官方协议之外**自己引入了力反馈**，属于协议增强，不是重复实现。

**程度：增强**

### 11. 特别要提的一项：成功判据

比赛源代码里判断"抓放成功"的代码是：

```cpp
pick_success_ = (dist <= pos_tolerance_ && angle <= ori_tolerance_);
```

这里的 `dist` / `angle` 是**当前位姿和初始位姿的偏差**。也就是说它判的是「**机械臂回到原位了吗**」，跟有没有抓住东西、有没有放对传送带**完全无关**。

cc's_arm 改成了任务级证据：抓取和放置分别留证，还要能回到具体的事件或图像。

**程度：完全重写**

## 五、一句话总结

cc's_arm 在比赛源代码之上做的事，可以概括成三句：

1. **把大模型从"装饰"变成"真决策"**（比赛源代码是程序用 YOLO 真值覆盖模型的回答）
2. **把开环动作变成闭环控制**（比赛源代码是写死的偏移加固定 sleep，成功判据只看机械臂有没有回原位）
3. **补齐了比赛源代码完全没有的部分**——身份跟踪、掉落恢复、碰撞检查、停止能力、任务账本、证据链

官方能打的底子（场景、物资、仿真物理）原样保留，没有覆盖。

**目前最大的两个缺口不是代码能力问题，而是信息问题**：一个缺第五类物资的模型和资产，一个是方位标准没跟裁判对齐。
