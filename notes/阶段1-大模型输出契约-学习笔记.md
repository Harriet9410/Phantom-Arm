## 1. 链路里「契约」在哪

```text
终端输入「抓取烟雾弹」
        │
        ▼
isaac_scale.py
   build_user_prompt(指令)  ← 本阶段加的
   model.chat(image, prompt)
        │  /model_output  (String)
        ▼
isaac_yolov8.cpp
   regex 提取 (u,v,depth,angle)
   像素 → 相机 → 机器人
        │  /arm_end_pose_quaternion
        ▼
isaac_grasp.cpp 抓取
```

**契约 = 上游必须输出的固定形状。**  
大模型口语化再好，下游正则吃不下就等于识别失败。

## 2. 改前问题（读代码能直接看出来）

### 2.1 Prompt 过松（`isaac_scale.py`）

```python
default_bbox_prompt = "请处理图像并返回结果"
```

- 没规定字段：类别 / 像素 / 深度 / 角度  
- 没规定格式：JSON？自然语言？元组？  
- `process_latest_frame` 把 **用户原话** 直接塞进 chat，模型自由发挥

### 2.2 解析过死（`isaac_yolov8.cpp`）

旧正则本质要求：

```text
( 整数 , 整数 , 浮点m , 浮点 )
```

会失败的情况：

| 模型输出 | 旧结果 |
| --- | --- |
| `(312, 245, 0.82, 12.5)`（缺 m） | 解析失败 |
| `[312, 245, 0.82m, 12.5]` | 失败 |
| 全角逗号 `（312，245，…）` | 失败 |
| 深度 `0` 或 `9.9` 异常 | 仍进队列，后续规划难查 |

## 3. 我们定的契约（本阶段）

### 3.1 输出形状

```text
(u, v, depth_m, angle_deg)
左侧          # 可选，单独一行
```

示例：

```text
(312, 245, 0.82m, 12.5)
(401, 260, 0.95m, 87.0)
左侧
```

### 3.2 为什么和 C++ 旧格式兼容

- 仍保留 `depth` 后可写 `m`，旧链路能认  
- 同时允许 **不写 m**，给模型一点容错  
- 角度仍按 **度**，C++ 再 `* π/180`

### 3.3 Prompt 结构（`build_user_prompt`）

固定几段，顺序重要：

1. **背景** — 你是谁、要什么  
2. **任务** — 用户原话（动态拼接）  
3. **输出契约** — 格式 + 字段语义 + 禁止项  
4. **示例** — few-shot，模型最容易照抄  

要点：

- 用户指令 **嵌进契约模板**，不是覆盖掉契约  
- 明确 **「不要 JSON / markdown / 解释」**，减少下游噪声  
- 分拣侧 **另起一行**，不要和元组搅在同一句

## 4. C++ 解析改了什么

### 4.1 更宽容的括号与分隔符

```cpp
[\(\[] ... [,，] ... [\)\]]
```

- `()` 或 `[]`
- 英文逗号 `,` 或中文逗号 `，`
- `u,v` 允许浮点（模型偶尔写 `312.0`）
- `m` 变为可选

### 4.2 值域过滤（比“能 parse 出来”更重要）

```cpp
if (Z <= 0.05 || Z > 5.0) skip;
if (angle 异常) 夹紧为 0 并 WARN;
```

- **深度非法直接丢**，避免抓到假目标  
- **角度异常不静默**，日志里能看出模型乱写

### 4.3 分拣侧

同时认：

- 中文：`左侧` / `右侧`
- 英文：`left` / `right`

方便 Prompt 中英混用。

## 5. 坐标变换（没改，但要会手推）

C++ 里仍是经典两步：

```text
像素 (u,v) + 深度 Z
    → 相机系:
        Xc = (u - cx) * Z / fx
        Yc = (v - cy) * Z / fy
        Zc = Z
    → 机器人系:
        P_base = R * P_cam + T
```

本阶段 **不动 R/T**，只保证 **喂进去的 u,v,Z,angle 是干净的**。  
契约不干净时，标定再准也会飞。

## 7. 踩过的坑 / 设计取舍

1. **契约写进系统说明，用户输入仍保留**  
   若只把用户 input 当 prompt，模型会忽略格式。

2. **不要把 JSON 当唯一格式**  
   多模态小模型有时吐半截 JSON；元组行更易用正则兜底。  
   若后续发现模型爱 JSON，可 **双格式解析**（先正则元组，再 json.loads）。

3. **解析成功 ≠ 目标真**  
   本阶段加了 Z 角度过滤，但仍依赖模型标对像素；后续要有 YOLO 交叉验证。

4. **C++ topic 与文档不一致时先别乱改**  
   代码订阅 `/Jaka/camera/camera_info`，文档写 `/Jaka/camera_info`。  
   以 **实机/仿真 rostopic list** 为准；本阶段故意不动 topic。

## 9. 一句话总结

> **Prompt 负责把模型压成固定形状；C++ 负责在形状微抖时仍能吃下并拒绝坏值。**  
> 契约是大模型和运动控制之间的「接口层」，不是可有可无的提示词技巧。
