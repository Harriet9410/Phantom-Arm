## 1. 原状态机哪里容易卡死或“假成功”

读官方 `doPickPlace` 可看到三条风险：

| 问题 | 原代码现象 |
| --- | --- |
| 无超时 | `waitForPosition` / `waitForGripper` 在 `while(ros::ok())` 里永不退出 |
| 未到位仍放置 | WARN「跳过闭合」后 **继续** init → place → open |
| 无重试 | 失败直接发 `/pick_place_result=false` 结束 |
| 成功判据弱 | 只看是否回到 `init_pose`，夹爪是否抓住不是硬条件 |

赛题里「空抓/飞点/没到位」很常见，需要**可恢复**。

---

## 2. 本阶段改造后的流程

```text
arrayCallback(7维目标)
  busy=true
  最多 (max_retries+1) 次:
      doPickPlace(target, attempt)
         ├─ 抬升接近 → 超时? → 回init+张爪 → fail
         ├─ 下移 → 超时? → 同上
         ├─ 未在容差? → 同上（不再放置）
         ├─ 闭合 → waitForGripper 超时? → 张爪+回init → fail
         └─ 放置链 → 回init → success?
  发布 /pick_place_result = 最终 ok
  busy=false
```

失败路径统一：**回初始 + 张开夹爪**，避免夹着空气去下一次。

---

## 3. 超时为什么必要

无超时时：

- 规划/跟踪卡住 → 节点永久占 `busy_` → 后续目标全部丢弃  
- 比赛现场无法“重启节点”补救  

本阶段默认：

| 参数 | 默认 | 含义 |
| --- | --- | --- |
| `pos_wait_timeout` | 20 s | 单次位姿跟踪上限 |
| `gripper_wait_timeout` | 8 s | 闭合确认上限 |
| `retry_delay` | 1.5 s | 两次尝试间隔 |
| `max_retries` | 2 | 失败后再试次数（共 3 次） |

可用 launch / `rosparam set` 覆盖，不必改代码。

---

## 4. 失败原因（日志关键字）

| 标记 | 含义 | 下一步排查 |
| --- | --- | --- |
| `APPROACH_TIMEOUT` | 抬升目标上方没到 | 外参 / 规划 / 工作空间 |
| `DESCEND_TIMEOUT` | 下移抓取点没到 | 接近高度、碰撞 |
| `NOT_IN_TOLERANCE` | 到了但误差超容差 | `pos_tolerance_`、跟踪抖振 |
| `GRIPPER_TIMEOUT` | 一直夹不紧 | 夹爪步长、物体过小/滑 |

云端实验表可按这四类统计，而不是只记成功/失败。

## 5. 成功判据变化

**改后：** `doPickPlace` 仅在完整放置链 + 回到 init 后返回 true。  
抓取阶段任一步失败都会 **提前 return false**，不再“假放置”。

> 仍可用后续增强：闭合后用 `/Jaka/gripper_is_captured` 做**放置前硬门闩**（当前闭合成功即继续）。

## 6. 线程与 busy_

```cpp
if (busy_) return;
busy_ = true;
std::thread([...]{ ... busy_=false; }).detach();
```

要点：

- 一次只允许一条抓放流水线  
- 必须在 **所有** 路径（含重试穷尽）清 `busy_`  
- 结果消息放在循环外，避免 N 次尝试发出 N 个最终结果（阶段1的 `isaac_yolov8.cpp` 靠结果推进 `current_idx_`）

---

## 7. 本地单测测什么（`test_grasp_retry.py`）

C++ 状态机无法在 Windows 上跑 ROS，但**决策表**可以：

- 成功 → 不再重试  
- 失败且 attempt &lt; max → 下一次  
- 失败且已是最后一次 → 终止  
- `max_retries=0` → 只试一次  
- 四类失败原因都会阻断闭合/放置
