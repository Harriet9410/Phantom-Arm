## 1. 原来藏在状态机里的魔法数

```cpp
approach.x += 0.03;
approach.y += 0.0075;
approach.z += approach_height_;  // 这个早已是参数
target.x  += 0.01;
target.y  += 0.0075;
set_pose.z -= 0.2;
// sleep 2s / 1.5s ...
```

问题：

- 赛道物体位置变了要改代码重编译  
- 和阶段 3 的 `NOT_IN_TOLERANCE`、`DESCEND_TIMEOUT` 对不上“到底哪组偏移”  
- 多人实验无法用 launch 文件做对照

## 2. 参数化后的旋钮

| 参数 | 默认 | 调什么 |
| --- | --- | --- |
| `approach_height` | 0.1 | 接近点抬高多少（防撞） |
| `approach_dx/dy` | 0.03 / 0.0075 | 接近点相对检测点的平面偏置 |
| `descend_dx/dy` | 0.01 / 0.0075 | 真正下抓点的平面偏置 |
| `place_lower_dz` | 0.2 | 放置区下探深度 |
| `place_raise_dz` | 0.2 | 放完抬起 |
| `settle_s_after_descend` | 2.0 | 下抓后稳住再闭合 |
| `settle_s_after_open` | 1.5 | 张爪后等待 |

**默认 = 原硬编码**，不传参时行为不变（安全默认）。

---

## 3. 和失败原因怎么联动

| 现象 | 优先调 |
| --- | --- |
| `APPROACH_TIMEOUT` | 降 `approach_height` / 检查工作空间 |
| `DESCEND_TIMEOUT` 或撞桌 | 降 `descend` 偏置、减小下探 |
| `NOT_IN_TOLERANCE` | 略增 settle、检查外参 |
| `GRIPPER_TIMEOUT` | `descend` 对准中心、夹爪步长 |

实验表里**必须写参数**，否则“成功/失败”无法归因。

---

## 4. 五终端脚本在干什么

只做两件事：

1. 打印正确启动顺序与路径（`/root` vs `/root/gpufree-data` 自适应）  
2. 提示 grasp 可带参数  

**不**自动开 5 个终端（云端 GUI/SSH 场景差异大）。复制各段到 FinalShell/VSCode 多终端即可。

---

## 5. 实验记录为什么用模板

赛题考核成功率、延迟、鲁棒性（阶段 D）。  
没有统一表会导致：

- 只记“好像更稳了”  
- 多人各记各的，无法对比 TRRT preset  

模板强制：**commit + 参数 + 成功率 + 失败原因 + 下一轮只改一项**。

---

## 6. 本地单测

`test_grasp_offsets.py` 做的是 **源码断言**，不是仿真：

- 9 个新 `pnh.param` 必须存在  
- 不允许再出现 `+= 0.03` 等旧硬编码  
- 默认值与官方基线一致  

真正的运动效果只能云端跑。
