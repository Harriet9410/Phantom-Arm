# 2026TCEI 机器臂部署说明 · 260920v2

本包用于从**官方赛事镜像新建的实例**部署。它包含改进程序、运行入口、标定、进程管理、桌面核对面板、记录器、官方资源检查清单和原30轮场景；不依赖之前那个实例的临时文件或运行目录。

## 1. 新建实例

在赛事指定平台选择“2026TCEI机械臂物资分拣场景应用挑战赛”对应官方镜像，启用平台提供的 GPU 和图形桌面服务。镜像的具体平台标签/镜像摘要未获得可靠记录，请以赛事平台当时提供的镜像为准，不要改用普通 Ubuntu 或只带 CUDA 的镜像。

官方镜像应自带这些资源：

| 资源 | 镜像内路径 |
| --- | --- |
| Isaac Sim 4.5 | `/root/isaacsim/python.sh` |
| 官方场景与控制基础 | `/root/EAICON/Content/JAKA/scene.usd`、`/root/EAICON/Source/JAKA/` |
| ROS Noetic / 官方工作空间 | `/opt/ros/noetic/setup.bash`、`/root/jaka/devel/setup.bash` |
| YOLO 环境与权重 | `/opt/conda/envs/yolov8/bin/python`、`/root/jaka/best.pt` |
| 九格环境与模型 | `/opt/conda/envs/inference/bin/python`、`/root/inference/FM9G4B-V` |

这些大模型权重、Isaac 安装与官方场景由官方镜像提供，没有重复放入压缩包。包内 `config/image-baseline-manifest.json` 校验其来源文件。若镜像资源缺失，应更换/恢复官方镜像，不要从不明地址补权重。

## 2. 上传与解压

用平台 JupyterLab 上传本 ZIP 到 `/root`。打开 JupyterLab 的终端，执行下面命令。若已经存在同名目录，先使用新的独立目录，不覆盖此前实验。

```bash
cd /root
/usr/bin/python3 -m zipfile -e '2026TCEI机器臂部署@260920v2.zip' /root
cd /root/tcei_260920v2
/usr/bin/python3 scripts/verify_package.py
```

从平台控制台打开新实例的远程桌面；链接应使用新实例自己的链接。本包不写死旧实例网址。

若显示 Bad Gateway，先在平台启动桌面服务。包提供镜像原有桌面的恢复入口：

```bash
bash robot.sh desktop
```

该入口只启动镜像已有的 `/etc/gpufree`，必要时通过 Bash 调用镜像原有模式脚本，不改登录验证或端口暴露设置。若端口已运行但浏览器仍不能连接，请查看平台桌面状态和 `state/desktop.log`，不要重复启动多个桌面进程。

## 3. 初始化、环境检查

```bash
bash robot.sh init
bash robot.sh doctor
```

初始化会发现唯一可用的桌面显示号；无法唯一判断时，查看终端的 `echo "$DISPLAY"`，再明确传入，例如 `bash robot.sh init --display :20`。`:20` 只是曾测试实例的值，新实例不一定相同。

默认数据保存到 `/root/gpufree-data/tcei_260920v2`；平台无此数据盘时保存到包内 `runs`。可用 `init --data-root /你的数据目录` 指定。初始化会生成本实例自己的身份标记，不需要复制旧实例标记。

`doctor` 检查官方小文件 SHA256、模型大文件大小、ROS/图像库、两个模型环境和桌面。需要完整检查九格大权重内容时：

```bash
/usr/bin/python3 scripts/verify_image.py --deep-model --output state/image-deep-check.json
```

环境检查通过只说明依赖齐全，不能替代一次真正的九格推理与机械臂完整任务。程序使用镜像内的三个 Python 环境，不要在 base 环境统一升级 Torch、NumPy、ROS 或 Transformers。

## 4. 启动并执行官方示例

每次冷启动和每轮任务使用一个新的名称：

```bash
bash robot.sh start demo_stack_01
bash robot.sh panel --episode demo_round_01
bash robot.sh run demo_round_01 --official-example
```

`start` 打开 Isaac 并预热 YOLO、九格，保持执行开关关闭。`run` 才开始计时并让机械臂退出篮子上方，再识别和抓取。不要同时从官方旧脚本启动另一套机械臂控制器。

官方示例原文是：

1. 抓取左上方的烟雾弹，放到左侧传送带
2. 抓取右下方的弹夹，放到右侧传送带
3. 抓取最左方的军用手电筒，放到左侧传送带
4. 抓取手雷，放到右侧传送带
5. 抓取剩余的物品，放到左侧传送带

默认预算600秒，准备让位、识别、修复、机械臂动作均计入本轮计时。场景随机后不能机械照搬与物体方位矛盾的指令；必须预先登记题目、兼容布局与目标判定。

自定义赛事指令用 UTF-8 JSON 字符串数组，不使用旧的固定类别指令覆盖：

```bash
bash robot.sh run round_02 --instructions instructions/official_example.json --task-source official_example
```

上例需要新启动的、尚未执行过任务的场景。程序拒绝复用已开始过的场景及轮次目录，防止把第二次运行混进首次结果。

## 5. 核对面板

远程桌面窗口标题为 **TCEI 联合核对：YOLO · 九格 · Isaac**。四个页签分别展示：

- 实时相机原图和 YOLO 编号图、类别、位置与角度。
- 九格收到的实际图像及真实模型原始回答、重答原因。
- 抓取点和待核对事项。
- 完整 Prompt、时间线和执行事件。

模型输入/原始回答就是可复核的分析记录；程序不会编造或展示模型不可访问的内部思维过程。面板只读，人工核对意见不会发送机械臂控制指令。关闭面板不停止机器人，可再次 `bash robot.sh panel --episode 当前轮名` 打开。

## 6. 查看、取消和关闭

另开一个 Jupyter 终端进入本包目录：

```bash
bash robot.sh status
bash robot.sh cancel --reason '人工检查'
bash robot.sh stop
```

`cancel` 由控制器分配停止编号，并核对同编号的实际停止回执。`stop` 确认停止后，只关闭本包登记的进程组，不清理历史结果、不强杀其他进程。停止回执为 fault/unconfirmed 时保留现场，请先查看日志和机械臂状态。

本轮结束后要恢复初始布局，使用 `stop`，再以新的名称 `start`。不能在任务执行中重置场景、直接修改物体坐标或绕过停止确认。

## 7. 原失败场景复测

`cases_b01` 保存原30轮原始 JSON，原始种子为2026091901—2026091930。旧实例字段只作来源记录，新实例运行身份独立校验。启动时会对照 `B01_REGISTER.json` 校验文件散列，不能用另一批20260918xx种子替代。

```bash
bash robot.sh start regression_02_stack --case cases_b01/random_02.json
bash robot.sh run regression_02_round --instructions instructions/original_mechanical_regression.json --task-source custom_original_mechanical_regression
bash robot.sh stop
```

先复测原实际失败的2、4、6、8、9、24、26、28；20曾初始化失败，单独记录初始化回归。旧场景复测保持历史简化指令，便于比较机械表现。随后新的随机30轮使用官方空间/剩余指令，单独统计；这两种测试不能合并冒充官方套题通过。

外部新登记场景可通过 `start 名称 --case 场景.json --case-register 登记表.json` 加载。登记表必须含 case_id、seed、planner_seed 与文件SHA256。布局仅在任务开始前由测试仿真入口生成，真值只写测试记录，不传给九格或控制器。

包内也提供批量入口。先确认上一场景已stop，再执行原失败8场景：

```bash
/usr/bin/python3 test_tools/run_registered_batch.py --package . --case-root . --register B01_REGISTER.json --case-ids random_02 random_04 random_06 random_08 random_09 random_24 random_26 random_28 --batch old_failed_v2_01 --instructions instructions/original_mechanical_regression.json --task-source custom_original_mechanical_regression
```

检查旧失败场景结果后，新30轮使用包内已登记的兼容布局和官方原文：

```bash
/usr/bin/python3 test_tools/run_registered_batch.py --package . --case-root . --register B02_AVAILABLE30_REGISTER.json --all-registered --batch official30_v2_01 --instructions instructions/official_example.json --task-source official_example
```

批量入口逐轮冷启动、运行、独立核对实际物体轨迹并停止；保存campaign.json，分别记录机器自动核验与离线物理核对。每次使用新batch名称；发生启动/停止异常时停在attention_required并保留现场。新30轮只覆盖现有4类5件及公开示例；不代表包含缺失的压缩干粮或未公开套题。

## 8. 输出、统计及已知边界

每轮目录保留 `instructions.json`、代码清单、`episode/events.jsonl`、`episode/summary.json`、RGB-D、传感器记录、进程记录和监督器关闭结果。重点同时看任务完成情况、实际正确落点、自动核验状态和耗时。

`completed_with_unverified_placements` 表示释放动作全部执行完，但有放置证据缺口；不是“全部自动验证成功”。程序继续后续对象并避免对待核验对象重复抓取。不能仅因成功发出指令或篮内变空就增加得分。

包内冻结运行版为 **dev_v7_t1_23**。21版修复九格“剩余物品”混用内部长编号，22版保护遮挡时的物体身份参考，23版在垂直姿态候选全部失败且预算允许时加入有限±10°微倾候选，重新补偿夹爪参考点并检查完整路径、支撑面及篮沿间隙。接触下降、闭合与首次抬升速度未因此加快，持物搬运保持已选姿态。自动停止的TGS判定使用相邻完整物理步位置差分，同时保留原始速度；未修改物理引擎、阈值或反馈数据。详细过程及验证范围见 `docs/轨迹调优.md` 和随包验证记录。

当前镜像检测权重只有弹夹、手电筒、手雷、烟雾弹四类，场景五件中烟雾弹有两件；未完成官方压缩干粮资产与识别适配。仅公开五条示例得到核对，其余未取得的官方套题、完整网格碰撞验证、极端姿态与拨动等仍以测试计划中的状态为准，不能声称全赛事验收通过。九格实际参与选择，但“使用九格加20分”的最终口径由赛事裁判确认。

旧记录格式一轮约2—3GB。本包对深度图使用逐位可还原的相邻帧异或压缩，每32帧保存独立关键帧，每帧校验解码SHA256；RGB原图仍逐张保留，采样频率未降低。控制器读取实时ROS相机，归档压缩不改变控制输入。用包内 `evaluation/rgbd_archive.py` 的 `read_depth_archive(path)` 读取任一深度归档；不要直接假设每个NPZ都含独立depth数组。第一张reference仍为完整深度帧。

实际空间以运行记录为准，按最坏时长仍需预留至少8GiB再开始一轮；不足时暂停新轮次以保全证据。批量测试每轮检查空间，不为了腾空间删除尚未备份的失败证据。

## 9. 与官方文件的关系

部署只在独立目录增加运行程序，通过包装官方 `jaka_sim.py` 的方式接入；不覆盖 `/root/EAICON` 的基础源码、场景和模型权重。统一运行入口是包内 `robot.sh`。直接运行官方原入口会使用官方原有行为，不会自动带上本包改进。

移动本包目录后重新 `init`；重新初始化前确保旧目录的任务已完成并关闭。升级采用新目录和新冻结清单，旧结果保留。包不含现成密码、令牌、云账户信息和旧进程PID。

`docs`中的开发过程记录保留了原工程/实验路径作为追溯线索；它们不属于新实例的运行依赖。部署所需入口以本说明和包内相对目录为准。验证摘要随包，完整原始测试影像保存在原实验数据目录，未重复塞入部署ZIP。
