## 1. 目标、范围与当前基线

目标是正确理解并完成比赛任务，在可靠性和动作约束成立后缩短耗时。优先级为：目标和投放侧正确、任务完成、控制安全、同等完成情况下降低耗时。

当前基线是最后一批测试使用的 clearance_fallback_v6，源码位于 [candidate_v6/tcei_stack](D:/720/dog/2026TCEI/implementation/stress_20260918/candidate_v6/tcei_stack/BUILD_MANIFEST.json)。

已确认的范围与缺口：

- 原30轮首次实际执行为22/30完整成功，跨4个版本；最终V6覆盖20轮，17/20成功。二者不能合并成最终版本30轮成绩。
- 原测试使用指定类别、明确数量和投放侧的简化指令，没有验证正式空间语义和“剩余物品”。
- 九格接收重新排版的物品裁剪图；现有语义校验没有完整验证“左上方、右下方、最左方”。
- 原测试物资固定为弹匣、手电筒、手榴弹和烟雾弹，不能证明压缩干粮已经适配。
- 第24、26轮在接近姿态规划阶段失败；第28轮反复出现夹持确认后信号丢失。现有采样未显示第28轮目标被有效提起，不能称为13次已证实的物理掉落。
- 现有恢复包含退回篮外观察位，但失败候选容易重复，任务级暂缓和剩余集合管理不足。
- 现有取消只停止发送后续目标，不能保证已接受轨迹立即停止；已有几何保护也不等于完整碰撞验证。

本轮不进行九格权重微调，不专项攻关20分视觉加分；为了支持正式指令，可以调整九格输入、提示和结构化输出约定。九格必须继续真实承担语义解析。

## 3. 修改模块及完成条件

### M00：固定需求、基线和运行边界

1. 保存官方规则版本记录、实际任务原文、物资清单、模式开关及待确认事项。
2. 以V6冻结代码为对照，新代码单独版本化；保留全部旧结果，不覆盖失败或将补测写成首测。
3. 分开配置比赛模式、语义验证模式、恢复故障注入模式和拨动实验模式。故障注入不能混入正常回合。
4. 确认官方五类资产、机器人接口和实际停止能力；不从文档中的接口名称推定当前接口一定可用。

完成条件：R01—R14每项都有负责模块、测试编号和状态；所有裁判口径和工程假设可追溯。

### M01：正式指令和空间目标选择

九格收到现场全景编号图，以及同一时刻、同一坐标定义下的候选位置；裁剪图仅补充外观，不承担空间布局。所有裁剪、旋转、缩放和编号都能映回原图。

输出和校验至少分别表达：原指令、任务编号、类别或剩余集合意图、数量、空间条件、参考系、所选对象、目标传送带、场景时刻以及待确认原因。

- 先筛类别，再在相关对象中计算“最左”等极值。官方[任务3配图](https://tcei.c2.org.cn/imgs/rules/c1r4.png)中，手电筒左边仍有烟雾弹，可用来排除全场最左的错误解释。
- “左上方”按已确认的区域或相对关系同时核对两个方向；不能无条件替换成横纵坐标相加后取最小。
- “上方”的平面方位与物体高度分开，不把更高的物体理解为画面更靠上。
- 物体方位与传送带方向独立解析；类别不固定对应某侧。
- 支持官方物资名称及常用同义词，包括弹夹/弹匣、手雷/手榴弹、军用手电筒/手电筒、压缩干粮/已确认的类别名称。
- 正式示例未写“一个”，仍需根据任务意图和唯一性确定数量；不能把同类数量自动当搬运数量。类别多候选而没有消歧依据时不任取。
- 每个有意义的限定条件都要进入结果和校验。无法解析的限定词、冲突条件或超出能力范围的语义不得被静默丢弃。
- 校验失败可在固定次数内要求九格重新输出；程序不暗中修改模型的类别、目标或传送带后执行。

完成条件：L01—L18通过；真实九格输入、输出、几何校验及最终选择能串成证据链。原四键单类别协议的消费者必须同步适配，不能只改提示词。

**M01接口实施调整（06候选）：**正式模型响应采用明确新协议`nine.selection.compact.v1`，仅接受`class/side/count/ids`四个选择字段，或严格的`status=needs_confirmation`与非空`reason`两字段。模型必须真实决定具体对象、类别、数量和目的地；错误类型、ID、类别、侧、数量及额外字段不自动修补或丢弃。

方位、数量模式、剩余意图由原始指令的独立审计取得，参考系来自可信场景配置。全部空间/数量/未知/历史失踪/剩余依赖等条件仍通过同一完整验证；验证成功后才提供内部v2执行结构，并记录模型选择与可信约束各自来源。不得把内部`spatial/quantity/intent/reference`冒称九格原始输出，也不得用审计器直接选择ID补模型答案。这是输出接口简化，不是无条件启用旧V6四键旁路。旧11键解析入口保留用于兼容和内部验证；真实新协议不接受旧11键后偷偷只取四键。

验收继续使用独立预期实例和真实正负例；同类位置交换、目的侧交换、数量不足、未知区域及剩余集合等要求不变。05及更早11键协议的失败不重新投影为四键后改写成成功。详细实现见 [COMPACT_SELECTION_PROTOCOL.md](D:/720/dog/2026TCEI/implementation/competition_20260919/evaluation/COMPACT_SELECTION_PROTOCOL.md)。

### M02：五类物资、部分识别和未知区域

1. 核验五类官方资产、识别类别、尺寸、可夹部位、夹爪开度及姿态适配。压缩干粮作为待补能力，不能凭类别枚举认定支持。
2. 覆盖五选四全部5种类别组合；不固定“两个烟雾弹加另外三类”作为启动或成功条件。
3. 已识别对象、未知前景区域、被遮挡区域分别保留。未知区域不是空篮，也不自动判作某个缺失类别。
4. 调整当前前景高度过滤和遮挡判断，区分机械臂、篮壁、立起物体及叠放；不能简单放宽高度后把机器人作为物体。
5. 部分识别时允许执行当前任务中已明确且满足条件的对象；未知区域可能影响“最左”等结论时保持待确认。
6. 置信度不足、传感器过期、深度失效、类别冲突与目标不存在分别记录。

完成条件：V01—V10通过；没有通过强制补齐数量或读取仿真对象名称来提高识别结果。

### M03：物体身份、任务依赖和剩余集合

维护任务状态：待解析、待确认、可执行、执行中、暂缓、已验证完成、无法完成。维护独立的持续物体身份；每帧候选编号不能直接当永久身份。

- 每条指令在规定解释时点绑定具体对象。当前任务恢复时保持原对象；下一条指令按其合法场景时点重新解释。
- 识别出新露出的物体时补入场景记录，不只使用最初可见集合。
- 已正确交付、尚未执行、掉落待恢复、身份不明和暂缓对象分开记录。
- 任务5的集合结合未交付对象、前序任务关系和未知区域确定。尚未履行的指定投放目标不自动成为可送左侧的“剩余”。
- 剩余多类别采用逐对象类别和目标侧记录，替换当前整条计划只能有一个类别的限制。
- 不以检测数量恰好减少1作为交付的必要条件，也不以零检测作为空篮或任务完成的充分条件。
- 规则允许换序时，只在依赖满足的任务中选择；综合可达性、稳定夹取、预期耗时及任务价值，禁止为方便而更换指令对象。
- 规则未允许跳过当前任务时，目标暂缓不等于可以擅自执行后续任务。

完成条件：L19—L22、V06—V10、G07—G10通过；任务和对象不会因重编号、遮挡或重试重复计数。

### M04：有效抓取确认与掉落恢复

统一流程：接触确认 → 小幅试抬 → 有效随动确认 → 正式搬运 → 放置验证。

试抬优先取自现有抬升动作的前一段。按用户2026年9月19日的纠正，顶视目标被夹爪遮挡是预期状态，不以必须看见物体随动作为搬运硬门槛。操作上的抓稳确认使用持续有效的双指受力、非空实际夹持宽度、实际试抬位移和期间接触保持；单个布尔量、指令量、物体消失仍不能独立判成功。视觉可见时提供辅助证据，清楚看到原物体未移动则作为反证；遮挡或缺少随动画面不否定其它有效证据。日志区分传感器推断抓稳与独立视觉随动确认，实际放置另行验证。传感器无效或联合证据不足时保持夹持并有界停止，不能为遮挡主动放开已抓稳物体。

恢复分支：

1. 未有效提起：确认当前运动已结束或可靠停止，安全退出并回篮外观察位；重新定位，切换抓点或姿态。
2. 已提起后丢失：停止追加搬运目标，确认当前轨迹状态，安全回本轮开始前已验证的观察位；等待物体稳定后重新识别。
3. 身份不唯一、物体不可达或观察无结果：在剩余预算内采取有限恢复，记录具体未完成原因，不用另一件同类替代。

每个物体保存失败抓点、姿态、深度、阶段和结果。没有场景变化时，不重复已经证实无效的同一候选。抓取候选总数、单物体恢复时长和全局截止时间均有上限，在开发阶段标定并于整批测试前冻结；至少保证第22轮已知成功恢复不因随意缩短预算而退化。

所有恢复沿用本轮600秒截止时间，并预留后续合法任务和可靠停止所需时间。第28轮应重点验证假接触与无效提起，不能靠降低搬运速度或增加相同重试次数认定修复。

完成条件：G01—G10通过，原第22、28轮有完整恢复证据；接触、有效抓取、实际掉落三个指标分别统计。

### M05：规划候选扩展与难例分类

保留正常快速路径，失败后按以下顺序回退：

1. 输出每个候选的拒绝原因，区分逆解未收敛、关节限制、间隙不足、路径不通和起始状态不一致。
2. 增加有限数量的肩、肘、腕构型初值，保留多个合法分支并评估完整抓放路线。
3. 从相机得到的物体主体内生成少量备选抓点。开发时可研究沿主体长轴偏移5或10毫米，但必须满足物体尺寸、接触面和邻近障碍约束。
4. 再考虑中间过渡姿态；中间点不能解决真正不可达的抓取终点。
5. 常规候选耗尽后记录物体暂缓或无法完成；只有规则允许时才转去其他任务或拨动恢复。

保持原位置、姿态误差、关节和间隙约束，不能为了通过规划放宽到接近碰撞。第24、26轮要求完成整轮，不以逆解成功或第一步移动代替验收。

完成条件：K01—K06通过，原第2、4、6、8轮回归不退化。

### M06：实际停止能力与运动空间检查

先确认控制接口如何停止已接受的轨迹，并测量动作停止而非仅命令取消的结果。若当前接口无法提供可验证的停止能力，应记录阻塞项，不能把长段合并或拨动投入比赛模式。

检查范围包括机器人连杆、夹爪、被夹物体与篮壁、桌面、传送带、其他物体及自碰撞；检查路径中间状态，不仅检查起终点。区分正常夹取接触、获准的拨动接触和禁止碰撞。

控制反馈丢失、运动状态不明、严重接触、超时或仿真故障触发明确中止与证据保存，不盲目续发指令。掉落恢复不等于允许在系统故障下继续运行。

完成条件：H01—H06通过；停止延迟、停止距离、超时行为及实际覆盖范围可复核。纯仿真通过不替代实机急停和动力学验证。

### M07：有限拨动和未知物体整理

仅在规则口径允许、M06通过且没有更直接的合法抓取候选时启用。先处理其他允许执行的对象，再考虑难例。

拨动目标是篮内较空、远离边界、便于后续抓取的区域，不固定朝几何中心直推。检查接触侧能否到达、目标方向、物体占据空间、夹爪高度、完整移动和退出路线。

流程：短距离受控拨动 → 撤回观察位 → 等待稳定 → 重识别 → 重新验证抓取。已经可抓时立即结束拨动。

- 同一物体或持续关联的未知区域最多3次实际拨动。编号变化、区域分裂合并或重识别不能把计数无故清零。
- 无实际位移、接触异常、没有可验证路线或时间不足时提前停止。
- 未知物体先定位几何区域，再判断是否适合整理；不因识别数量不足就盲拨。
- 立起、叠放、贴边采用相应整理候选，不把所有未知情况当成同一种故障。
- 识别出类别并确认目标侧后才能分拣；不能依据“还缺哪个类别”替未知物体贴标签。
- 验证现有仿真的夹爪自动附着逻辑是否影响拨动；不能把物体自动跟随当成正常推拨位移，也不通过改物理机制取得成功。

完成条件：P01—P08通过，实验拨动成绩与默认比赛模式分开报告。

### M08：比赛计时、任务计分和结束条件

比赛采用一个开始事件和一个全局截止时间。记录准备开始、裁判开始、首次运动、每次有效抓取、每次释放/递送、验证完成、中止和安全回位时刻。

- 开始后的让位、九格推理、规划、重新观察和恢复均消耗同一600秒预算。
- 子流程不得重新领取600秒，也不能在模型推理后重新起算此前取得的剩余时间。
- 最后递送、证据验证完成和回位是不同事件，分别保存；官方比赛用时按已确认的结束口径报告。
- 3分钟准备流程单独演练，区分开机预热与场上准备，不以延长测试初始化时间冒充满足准备要求。接入裁判开始及准备到时按规则开始的事件；系统尚未就绪也不能自行延后比赛起点或重开准备计时。
- 每次动作前检查可完成动作及可靠停止的预算，不能到600秒时只退出程序而让旧轨迹继续。
- 任务1、2、3、5各15分，任务4为20分，基础总分80；抓取与放置证据分开。重复抓同一目标不重复加分，任务5不按对象数重复累加整项分值。
- 本地评分是规则口径下的估计，不替代裁判成绩；未明确的部分得分保留待认定。九格多模态20分单列未专项验收。

完成条件：C01—C08通过，报告同时支持任务完成度、任务级得分证据和统一计时。

### M09：空载路线与高处搬运提速

在语义、抓取和安全基线成立后，拆分求解、指令等待、实际运动、到位确认和等待新观测的耗时。

优先缩短空载接近和回程，减少高处搬运中不必要的停车；保留初始及恢复观察位。研究复用预检查轨迹，但起始关节、物体位姿、夹持状态或场景变化后必须失效重算。

接触下降、夹爪闭合、首次抬升暂不优先加速。保持官方模型、物理参数、仿真时钟和已核对的运动限制，不用瞬移或降低安全检查换取速度。现有工程加速度参数不能自动当作官方批准值。

完成条件：Z01—Z04通过；采用相同任务和相同初始布局比较，不拿不同任务组合的均值直接宣称提速。

### M10：证据、版本与交付

每条规则建立证据索引，区分计划覆盖、代码实现、静态验证、真实推理通过、完整仿真通过和待裁判确认。

每个回合固定代码、模型、配置、场景、原指令、随机种子、预算和模式，保存各阶段事件、原始九格响应、RGB-D及动作反馈。仿真真值仅供独立评估，不进入运行算法。

交付更新后的实施记录、完整测试记录、统计报告、规则覆盖表和未完成清单。历史文档中的实验口径保留，不反向改写为正式比赛成绩。
