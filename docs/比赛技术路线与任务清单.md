## 2. 技术路线总览

```
阶段 A 感知与理解增强
    ↓  YOLO 精度 · Prompt · 大模型微调(可选)
阶段 B 执行与控制优化
    ↓  标定 · 抓取策略 · TRRT*/RmpFlow · 夹爪力控
阶段 C 鲁棒分拣 + 创新点
    ↓  多目标 · 失败重试 · 传送带分拣 · 创新点落地
阶段 D 比赛冲刺
      稳定性 · 延迟 · 成功率统计 · 操作手册
```

**推荐优先级（结合团队目标）：**

1. **先提精度与速度**（标定 + 抓取参数 + 路径规划参数）
2. **再做鲁棒分拣**（多目标 / 重试 / 传送带）
3. **最后加创新点与微调**（有余量再做，避免基础不稳）

### 2.1 技能地图（按角色 / 按阶段）

> 阶段 A/B（环境 + 官方跑通）已完成，默认已具备：ROS 启动、Isaac 加载、conda 多环境、模型路径约定。下列为**仍需补齐或深入**的知识。

| 系统 / 工程 | ROS1 话题/节点调试、C++ rospy 混合排错、状态机设计、超时与重试 | B–D |
| 任务 / 创新 | 抓取策略分类、TSP/贪心排序、上下文 Prompt、实验设计与指标表 | C–D |

- **Python 3.10 + 基础 C++**（读改 `isaac_*.py/cpp`）

### 2.2 算力受限时的项目推进（云端抢不到卡）

> 本地配置偏弱、算力自由实例又排不上时，不要停更；把开发拆成「吃 GPU」与「不吃 GPU」，云端只做验证与调参。

| 必须 GPU（有卡时集中做） | 本地 / 无卡也能做 |
| --- | --- |
| Isaac Sim 启动与物理仿真 | 读源码、改代码、写 Prompt 契约 |
| YOLOv8 推理 | 单元测试、解析逻辑、状态机 |
| 九格 FM9G4B-V 加载 / 微调 | 写文档、标定公式推导、实验表设计 |
| 端到端「指令→抓取」联调 | 用历史日志 / 回放复盘失败原因 |

**推荐节奏：**

1. **本地开发**：改 `isaac_*.py/cpp`、`jaka_env.py`、Prompt、状态机、实验脚本。
2. **本地最小验证**：不起 Isaac，用 mock 图像 / 固定 bbox 测解析、坐标变换、重试逻辑。
3. **云端只做验证**：抢到卡就同步最新代码，写成脚本一次跑完一批实验。
4. **抢卡策略**：排班（早/晚）、短任务优先、长训练拆小步；有空位立刻提交端到端。

**原则：本地写逻辑，云端做验证；不要把「能不能进实例」当成开发节奏的开关。**

## 3. 系统架构（5 层 + ROS 数据流）

### 3.1 分层

| 层 | 职责 | 核心文件 | **关键知识** |
| --- | --- | --- | --- |
| 1 指令层 | 终端输入中文指令（如「抓取烟雾弹」） | 人机交互 | 指令→任务语义拆解 |
| 2 大模型层 | 图文 → 结构化场景理解 | `isaac_scale.py` | 多模态 chat 接口、Prompt 约束输出、BGR↔RGB/PIL |
| 3 感知层 | RGB+Depth → bbox / 深度 / 倾斜角 | `isaac_yolov8.py` | YOLOv8、深度图编码、Canny+minAreaRect、相机内参反投影 |
| 4 决策层 | 坐标变换 + pick-and-place 状态机 | `isaac_yolov8.cpp` · `isaac_grasp.cpp` | 齐次变换、外参 R/T、有限状态机、ROS pub/sub |
| 5 仿真层 | RmpFlow 控制 · TRRT\* 规划 · 夹爪物理 | `jaka_sim.py` · `jaka_env.py` | IK、采样规划、样条跟踪、接触/力传感器语义 |

### 3.2 端到端数据流

```
用户指令「抓取烟雾弹」
    │  终端四输入
    ▼
isaac_scale.py  ── 订阅 /yolo_annotated_image
    │              model.chat(image, prompt) → FM9G4B-V
    │  发布 /model_output
    ▼
isaac_yolov8.cpp ── 正则/JSON 解析 (u,v,depth,angle)
    │              像素→相机→机器人坐标 (外参 R,T)
    │  发布 /arm_end_pose_quaternion
    ▼
isaac_grasp.cpp ── 状态机: 接近→下落→闭爪→抬升→放置
    │              夹爪增量 +gripper_is_captured
    │  发布 /Jaka/set_end_effector_pose, set_gripper_value
    ▼
jaka_sim.py + jaka_env.py
    │  RmpFlow IK / TRRT* 路径 / CubicSpline 跟踪
    │  力传感器自适应闭爪
    ▼
Isaac Sim 物理反馈 → 位姿 / 关节 / 抓取成功
```

### 3.3 关键 ROS 接口速查

| 话题 | 方向 | 说明 |
| --- | --- | --- |
| `/Jaka/camera_rgb` `/camera_depth` `/camera_info` | 发布 | 相机三件套（rgb8 / 米 / 内参） |
| `/Jaka/get_end_effector_pose` | 发布 | 末端位姿 |
| `/Jaka/set_end_effector_pose` | 订阅 | 目标位姿 |
| `/Jaka/set_gripper_value` | 订阅 | 夹爪开合 **0~0.04 m**，步长 **0.001** |
| `/Jaka/gripper_is_captured` | 发布 | True=抓住 |
| `/yolo_annotated_image` | 发布 | 标注图（喂给大模型） |
| `/model_output` | 发布 | 大模型文本结果 |
| `/arm_end_pose_quaternion` | 发布 | 7 维目标位姿 |
| `/pick_place_result` | 发布 | 任务成败 |
| `/conveyor_side` | 订阅 | 传送带左右分拣侧 |

## 4. 任务清单

### 4.1 阶段 A — 感知与理解（精度）

| # | 任务 | 改哪里 | 验收 | **所需技能（知识）** |
| --- | --- | --- | --- | --- |
| A1 | YOLO 检测稳定性 | `isaac_yolov8.py` / `best.pt` | 小目标/遮挡仍能出框 | YOLO 推理 API、置信度/NMS、训练轻量微调或换 `best.pt` |
| A2 | 深度取值鲁棒（中心像素） | 同上 | 深度异常过滤 | 深度图编码（32FC1/16UC1）、无效值/离群点处理、像素邻域采样 |
| A3 | 倾斜角 `minAreaRect` | `compute_2d_tilt` | 角度合理 | OpenCV：Canny、形态学、轮廓、旋转矩形与角度约定 |
| A4 | 大模型 Prompt 工程 | `isaac_scale.py` | 输出含 (u,v,depth,angle) 稳定格式 | 多模态 Prompt 设计、少样本示例、输出契约与解析容错 |
| A5 | （可选）LoRA 微调 | 官方 `finetune` / 自写 `finetune_lora.sh` | 特定物品种类识别率↑ | LoRA/DeepSpeed、标注数据构造、训练日志（tensorboard） |
| A6 | （可选）量化 | int4 等 |  | GPTQ/AWQ/bnb 概念、显存预算核算 |

**阶段 A 快补知识包：**

1. **像素→相机坐标**：(X_c=(u-c_x)d/f_x,;Y_c=(v-c_y)d/f_y,;Z_c=d)
2. **大模型输出「契约」**：固定模板（类别、u、v、depth、angle），避免自由文本难解析
3. **OpenCV 倾斜角**：`cv2.minAreaRect` 返回角点与 angle 的定义（0–90° 语义）要对照代码读一遍

### 4.2 阶段 B — 决策与控制（精准度/速度）

| # | 任务 | 改哪里 | 验收 | **所需技能（知识）** |
| --- | --- | --- | --- | --- |
| B1 | 相机外参 R,T 标定验证 | `isaac_yolov8.cpp` / `isaac_pose_pub.cpp` | 像素→机器人误差小 | 刚体变换、旋转矩阵 vs 四元数、误差度量（mm/°） |
| B2 | 抓取接近高度/放置位姿 | `isaac_grasp.cpp` | 减少碰撞与空抓 | 末端坐标系、approach vector、安全高度与工作空间 |
| B3 | 夹爪增量与延时 | `waitForGripper` 等 | 误抓/漏抓↓ | 接触语义、增量控制、超时与容差设计 |
| B4 | TRRT\* 参数（官方开放优化） | `jaka_env.py` | 规划更快更稳 | 采样规划（RRT 族）、温度/rewiring 直觉、参数扫参 |
| B5 | RmpFlow / JAK M Flow 跟踪（官方开放优化 | 同上 | 无明显抖振 | IK、反应式策略、跟踪误差与仿真步长 |

**阶段 B 快补知识包：**

1. **外参公式**：`P_robot = R * P_camera + T`；改标定只动 R/T 与内参，不动状态机逻辑

3. **TRRT\***：不必从论文推导，先理解「温度拒绝大步 + 邻域 rewire」再调 `step_size/radius/max_iter`

## 6. 核心算法与源码地图

### 6.1 TRRT\* / RmpFlow

- **TRRT\***（`jaka_env.py`）：带温度的采样规划，拒绝大跳跃 + 邻域重连；参数：`max_iter/step_size/radius/init_temp...`

    - *知识*：采样运动规划直觉（配置空间、碰撞检查）

- **RmpFlow**：反应式运动策略，实时避障 + IK；末端帧 `gripper_center`

    - *知识*：IK 多解与局部性；仿真步长与最大子步长

- **夹爪**：增量 0.001 m 闭合，力/碰撞/`gripper_is_captured` 停止

    - *知识*：接触事件驱动控制，而非「闭死夹爪」

### 6.2 相机外参（源码内嵌，标定后应覆盖）

```
P_robot = R * P_camera + T
R ≈ [[ 0.9499, -0.0767,  0.3030],
     [ 0.1082,  0.9902, -0.0887],
     [-0.2932,  0.1170,  0.9489]]
T ≈ [0.5072, 0.2223, 0.3310]
X_cam = (u-cx)*d/fx ,  Y_cam = (v-cy)*d/fy
```

**知识检查点：** 能手推「像素 + 深度 → 相机系 → 机器人系」两步；知道内参来自 `/Jaka/camera_info`，外参来自标定而非相机自带。

## 7. 大模型：推理 vs 训练（怎么用好「调大模型」目标）

| 路径 | 何时用 | 要点 | **所需技能** |
| --- | --- | --- | --- |
| **原生推理** | 默认 | 4090 + bf16 + SDPA，约 9~10G 显存；已验证饮料识别 | transformers、显存观察 `nvidia-smi` |
| **Prompt 增强** | 最快收益 | 固定 **BBox** 输出（类别、u、v、depth、angle），少歧义 | 指令设计、few-shot、输出解析 |
| **LoRA 微调** | **主攻考核：指令解析 + 九格 BBox 识别** | 单卡 4090：模型/输出进数据盘，梯度累积↑，LR≈1e-4 | LoRA、DeepSpeed 配置、数据 JSON 格式 |
| **量化** | 与训练/控制共卡或要压显存 | **微调后可量化部署**；4090 纯 bf16 推理通常不必 | bitsandbytes / GPTQ 概念 |

加载模板：

```python
from transformers import AutoModel, AutoTokenizer
model = AutoModel.from_pretrained(
    '/root/gpufree-data/FM9G4B-V',  # 绝对路径
    trust_remote_code=True,
    attn_implementation='sdpa',
    torch_dtype=torch.bfloat16,
).eval().cuda()
tokenizer = AutoTokenizer.from_pretrained(
    '/root/gpufree-data/FM9G4B-V', trust_remote_code=True)
res = model.chat(image=None, msgs=[{'role':'user','content':[img, prompt]}],
                 tokenizer=tokenizer)
```

训练代码：`git clone -b FM9G-V https://osredm.com/jiuyuan/CPM-9G-8B.git`，微调目录 `FM9G4B-V/finetune/`。

**调模型最小知识序：** 先会跑推理与看显存 → 再改 Prompt 契约 → 再谈 LoRA；量化放最后。

## 8. 工程约定：镜像只读 + 本地/云端代码分离

> 平台官方镜像当只读环境；我们的代码、权重、实验配置用挂载/目录分离，不改动镜像本身。

### 8.1 能不能把镜像拉到本地？

| 本地条件 | 能做什么 |
| --- | --- |
| 有 NVIDIA 独显（建议 ≥16GB，最好 24GB） | 可本地起同构环境做联调；端到端仍以平台为准 |
| 无独显 / 核显 | 只做代码开发与无仿真测试；Isaac + 九格不指望本地跑通 |

Isaac Sim 4.5 + FM9G4B-V 对本地要求高；「能 pull 镜像」不等于「本机能复现平台体验」。

### 8.2 不改动镜像的正确姿势

**原则：镜像层 = 官方环境（ROS/Isaac/conda）；挂载层 = 我们的代码与权重。**

```bash
# 示例：镜像只读，代码/权重 volume 挂入
docker run --gpus all -it --rm \
  -v /path/to/source_code:/root/jaka \
  -v /path/to/EAICON:/root/EAICON \
  -v /path/to/weights:/root/gpufree-data/FM9G4B-V \
  gpufree-tcei:your-tag bash
```

| 层 | 内容 | 是否允许改 |
| --- | --- | --- |
| 镜像层 | 官方 ROS/Isaac/conda/系统包 | **否**（不 commit 回镜像） |
| 挂载/工作区 | `jaka` 源码、场景、配置、实验脚本 | 是（Git 管理） |
| 权重与大数据 | FM9G4B-V、场景资产、日志 | 否进 Git；走数据盘/网盘 |

### 8.3 平台实例侧约定

- 实例内优先把**你们自己的代码**放在数据盘 `/root/gpufree-data` 下，便于导出与版本管理。
- 环境变量、路径软链按 `博客资料与实操要点.md` 统一，避免每人一套 `/home/q` 硬编码。
- 抢到 GPU 时：`git pull` 最新代码 → 跑固定实验脚本 → 结论回写仓库/知识库；镜像本身保持官方基线。

### 8.4 代码管理（与镜像解耦）

- **仍用 Git** 管理源码与配置；`build/`、`devel/`、权重、大场景、运行日志不进仓库。
- 本地与云端同一仓库、同一启动脚本；云端只换数据路径与 GPU。
- 实验参数写进脚本/配置并 commit，保证「这次跑的是哪版可复现」。
